修表情发送：判据换成像素，U+FFFC 在这版根本等不到

诊断脚本给出了决定性证据（tools/diagnose_paste.py，本机 4.1.15.53）：

    文本粘贴后 Value : '诊断文本ABC'   ← 文本会进 Value
    文件粘贴后 Value : ''   5 秒 9 次都是空
    像素检测         : True            ← 但缩略图真的画出来了

也就是说：微信把文件当内嵌对象塞进编辑框，**却不把它算进 Value**。
vendor 的 _uia_has_draft 等 U+FFFC，在这个版本上永远等不到 ——
它报"没有草稿"时，草稿其实已经在框里。

改成两段式判据：
  ① 粘贴后  = Value 里的 U+FFFC  或  输入框上方的彩色缩略图（任一成立）
  ② 发没发出去 = 数据库（verify_media_sent，不信前面的判据）

_draft_visible 两条判据并行等，哪条先亮就用哪条。

两条都看不见时仍然回车。取舍：真失败时对方收到一条空消息，
会问「你发了啥」—— 看得见；静默不发她永远不知道有张表情没出去 —— 看不见。
宁可错在明处。

另外两处：
  · _gui() 改成缓存。WeChatGUI.__init__ 要做布局校准（OCR+截图），
    实测首次 20 秒以上，每发一张图都新建一个就是每张卡 20 秒。
  · 退路不再自己判成功。guia.send_file 内部有独立的一套判据
    （UIA / 像素），比我在外面猜谁成功了靠谱。

删掉 _wait_draft —— 只剩 U+FFFC 一条判据的函数，留着只会有人再用它。

live_sticker_test 加了基线 seq：只认发送后新增的消息，
否则会把上一次测试留下的表情当成这次的结果（假阳性）。
