修三处：截图坐标、草稿判据、无条件成功

用户贴回来的截图全是桌面和 PowerShell，微信一个像素都没有。
根因是 _grab_screen 的 box 要**屏幕绝对坐标**，我传了窗口相对坐标
(0,0,render_w,render_h)，于是截的是屏幕左上角那块。

一、截图（diagnose_send.py）
  改成 gui._rel_to_screen((0,0,w,h)) 换算。
  截图前先 ensure_visible()，并打印**当前前台窗口标题**和微信的
  屏幕坐标 —— 「提到前面的到底是不是微信」不该靠猜。

二、草稿判据（wechat_sender._input_region_signature）
  弃用 _input_box_has_color_draft。它扫输入框上方 150px 数彩色像素，
  那个位置正是消息区底部。实测同一时刻两个判据互相矛盾：
      彩色像素 : True
      深色像素 : False
  框里真有表情缩略图的话，它既该彩色也该有深色描边。只有前者为真
  → 数到的彩色是别的东西（上一条气泡/边框/图标）。

  改成**区域变化量**：粘贴前后截同一块（只看输入框本体，不往上看），
  缩成 48×16 灰度图逐像素比，平均差 >6 算"进东西了"。
  静止画面重拍两次差约 0~2，真进了缩略图是 30+。
  它不预设"草稿长什么样"，所以不会被别的彩色骗。

三、无条件成功（_paste_media_uia / send_media）
  旧代码：
      edit.SendKeys("{Enter}")
      return True          ← 永远是 True
  于是"发送成功 3.3 秒"和"用户什么都没收到"能同时成立，
  上层还记了 [表情] 已发 —— 一次失败被写成成功，之后所有排查
  都从错误前提出发。这个比发不出去严重。

  现在 send_media 的收尾只有一条判据：verify_media_sent 回读数据库，
  10 秒内没新增就当失败，抛 SendError 说明原因。返回成功 = 真的发出去了。

  顺带补了 _db()/_resolve_chat()/_target_seq()，_db 懒加载并缓存，
  拿不到数据库时所有判据退化成"不知道"，不因此把真发送记成失败。

  粘贴循环里也补了 _restore_clipboard_files：剪贴板被消费掉之后，
  重试的第二三次 Ctrl+V 其实是空的。清空和粘贴之间拉到 0.35 秒，
  避免 Delete 晚到把刚粘的附件删掉。
