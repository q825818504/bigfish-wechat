修拖拽和「浏览…」：一个被 Qt 拦住，一个签名写错

用户反馈：添加表情弹窗出来了，但拖拽显示禁止图标、点「浏览…」没反应。

── ① 「浏览…」：@Slot 签名写错 ──

    @Slot(str, result=str)
    def sticker_pick_files(self) -> str:      # ← 方法没有参数

Qt 按声明找 `sticker_pick_files(str)`，Python 里没有，调用静默失败。
前端 await 拿到 undefined，JSON.parse 抛错被 async 吞掉，
用户看到的就是"点了没反应"。

这是**第二次**犯同一个错（上次是 list_memory_sessions）。
所以加了 tools/check_slots.py：静态比对 @Slot 声明的输入参数个数
和 Python 方法的参数个数。跑一遍还揪出 list_owners 也是同样的错
（那个是死代码，一并修了）。

── ② 拖拽：QWebEngineView 默认 acceptDrops=False ──

两条路都不通：
  · HTML5 dataTransfer.files 在 QtWebEngine 里没有 path 属性，
    拿不到路径就没法转 GIF（path 是 Electron 扩展，Chromium 标准没有）
  · QWebEngineView 是 QWidget 子类，acceptDrops 默认 False，
    系统层面就拒了，页面里的 dragover 根本收不到 ——
    所以鼠标显示的是禁止图标

改成 Python 侧拦 QEvent.Drop（bigfish/dropcatch.py），
从 QMimeData 拿 urls()，再用 runJavaScript 把路径数组丢给页面。
页面实现 window.__onDropFiles(paths) 接收。

两个细节：
  · 装到 view 的整棵子树。实测加载前只找得到 2 个控件，
    加载后是 392 个 —— 真正接收鼠标事件的是渲染层那一个。
    所以 loadFinished 后再装一次（install 做成幂等）。
  · 路径用 json.dumps 传，不手拼字符串。
    实测中文 + 反斜杠都完整保住。

前端的 dragenter/dragover 保留，但只负责虚线框高亮 ——
Python 侧万一没装上，用户至少能看到框亮了然后失败，
而不是完全没反应。

新增 tools/ui_console.py：用 QWebEngineView 加载真实界面，
把 console 消息全打出来 + 模拟点击。上一个 fmtBytes 重名就是靠它查到的。
