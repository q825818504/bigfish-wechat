### 一条必须记住的局限

**相关性只做字面共词。** 「牙疼」和「拔过智齿」一个字都不共，
分词器算出来是 0 —— 要让它们关联得接语义模型。

```

```

补位的是画像层：字面匹配不上的，靠"这个人有什么毛病"那段概述去兜。

## 2026-11-03 晚 · 表情接上心情

### 用户的原话

> 大肥鱼在不同的心情下，如果有同类的表情包，就根据不同心情展示不同的
> 表情包，比如同样是高兴，一个就一般高兴，一个就非常高兴
>
> 一定要配合到我们的心情插件，里面就有情绪维度！

### 先纠正一个说法

**不需要新增「情绪值」** —— 心情系统已经有两层：

```
score   0~100
dims    七根：开心 / 踏实 / 甜蜜 / 心疼 / 担心 / 难过 / 吃醋
```

真正缺的是两个：

```
① 挑表情时完全没读心情（插件只看对话文本）
② 表情没有维度也没有强度（十张都叫"高兴"，不知道哪张是微笑）
```

### 表情加两个字段

```
mood_dim    七根之一，或空 = 不归类（无语/疑惑这类）
intensity   1~5
```

**存 key 不存中文**：标签会改，key 不会。标签显示时查表。

`MOOD_DIM_KEYS` / `MOOD_DIM_LABELS` 和 `vault.MOOD_DIMS` 对齐，
**有测试断言两边一致** —— 不一致的话挑表情永远匹配不上。

### 视觉模型顺手判这两样

实测两张图：

```
微笑（小弧线嘴、圆眼）  → calm  强度 2  brief=微笑
大笑（大弧嘴、弯眼）    → happy 强度 3  brief=开心
```

prompt 里写死了：`mood_dim` 只能从七个里选，或者空。
「无语」「疑惑」这类不许硬塞进 happy。

### 挑表情时读心情

```
她现在的心情：心情不错（72/100）
情绪偏向：开心 45、甜蜜 12

可用的表情：
- stk_0003 [动图·强度2·开心] 微微一笑
- stk_0007 [动图·强度5·开心] 笑到打滚
- stk_0012 [动图·强度3·难过] 眼泪汪汪
```

prompt 规则：

```
第一步：维度要对上。她正在开心就挑「开心」类的。
       没标维度的（无语/疑惑）任何心情都能用。
第二步：强度跟分数对上。≥70 挑 4~5，40~70 挑 2~3，<40 挑 1~2。
       心情差的时候发狂喜，看着像装的。
但以这句话为准：明显在开玩笑，哪怕心情低也能发自嘲。
```

**心情读的是最新落盘的那份**，不是本轮开始时的快照 ——
心情判断是上一轮结束后写的，用最新的更准。

### 一个设计判断

**没让模型每次从 detail 里推强度，而是存成字段。**

理由：「这张图有多强烈」是图的固有属性，一次判断长期复用；
让模型每次重推，结果会飘。

### 版本号统一

以前散在三处：`__init__.py` 0.1.0、`updater.py` 0.2.1、
`make_installer.py` 0.1.0。发版时改一处忘两处，装出来的包
版本号和程序自称的不一样。

现在只在 `bigfish/__init__.py` 定义，另两处都 import。

## 2026-11-03 晚 · 表情库 + 插件化

### 用户的需求

> 侧边的表情包，我只希望他这个是表情包库……添加表情功能，点击之后，
> 弹出一个框，既可以选择从任意来源拖拽，又可以单个或者批量添加，
> 然后自动将任意格式的图片转化为 gif 保存到表情包库；对于每一个表情包
> 要制定一个独一无二的代码……备注只有双击才能显示详细信息……
> 对表情包备注功能，要导入的时候大肥鱼自动实现

> 勾选这个启用表情包插件之后，才会在侧边栏有这个表情包板块

### 关键决定

**表情包是插件，不是内建页面。** 侧边栏那一项跟着插件开关走。

**这一页只管库，不管行为。** 开关和频率搬去插件配置。

### 数据结构（schema v2）

```json
{
  "version": 2,
  "seq": 12,
  "items": {
    "stk_0007": {
      "code": "stk_0007",
      "file": "stk_0007.gif",
      "brief": "开心",
      "detail": "眉毛倒竖……",
      "tags": ["开心", "兴奋"],
      "mood_dim": "happy",
      "intensity": 3,
      "source": "import",
      "auto": true,
      "frames": 4, "w": 512, "h": 512
    }
  }
}
```

旧格式 `{文件名: {desc}}` 第一次读时自动迁移。

### 格式统一转 GIF

微信只把 `.gif` 认成原生表情。有损，但做了三件事缓解：

1. >1024 等比缩小（微信上限，超过当文件发）
2. 调色板 ADAPTIVE（按实际颜色分布）
3. 多帧保留（GIF / 动 WebP 逐帧转）

透明只能二值化 —— GIF 1 位透明的格式限制。

### 自动备注

本地网关支持视觉（实测：发红色圆形返回"红色圆形"）。
图缩到 512 再 base64。任何失败都不拒绝导入。

### 学习：主人纠正时改备注

```
主人：这个不是生气，是无语
  ↓
找最近发的那张（5 分钟内）
  ↓
关键词粗筛 → 模型判断是不是纠正 → 改 brief/detail
```

两道门：粗筛省 99% 调用，模型判断挡住"这个表情真好看"这类误伤。

**同步做不放后台**：放后台她这一轮已经用旧理解回复了，
下一轮才改，用户会觉得"我说了你怎么还不改"。

### 删除的墓碑

Windows 上文件被占用删不掉（QtWebEngine 预览持句柄）。
标记 `deleted: true`：列表跳过、发送读不到，下次 list 再试真删。

## 2026-11-03 晚 · 拖放（试了三条路）

用户反馈"拖拽无效"三次，前两条路都修错了地方：

| | 做法 | 为什么不行 |
|---|---|---|
| ① | HTML5 `dataTransfer.files` | QtWebEngine 里没有 `path` 属性 |
| ② | QWidget eventFilter + OLE | 管理员权限下被 UIPI 拦住 |
| ③ | **Windows 原生 `WM_DROPFILES`** | 通了 |

第 ② 条甚至写了 `ChangeWindowMessageFilterEx` 放行三条消息
（API 全返回 True），事件还是没到。

**真正的冲突**：窗口只要注册了 OLE drop target，系统就只走 OLE，
再也不发 `WM_DROPFILES`。而 OLE 在管理员权限下被 UIPI 卡死。
两条路互相打架。

解法：先 `RevokeDragDrop` 撤掉 OLE 注册，让系统回到老式路径。

自己构造 `WM_DROPFILES` 验证整条链路：
```
WM_DROPFILES 文件数=2
已交给页面：2 个
页面 pending: {"n":2, "p":["动图_512.gif","动图_240.gif"]}
```

日志写到 `<程序目录>/data/_drop.log` —— 界面在管理员权限下跑，
看不到控制台，出问题只能靠这个。

## 2026-11-03 凌晨 · 表情包发送通道

### 关键发现：GIF 文件就是原生表情

微信把剪贴板里的 `.gif` 文件识别成表情消息（`local_type 47`）。
对方收到的是原生表情 —— 能长按添加、会动。

### 真机踩出来的四个坑

**① 剪贴板格式不全**（`CF_HDROP` 不够）
微信是 Qt 应用，走 OLE，认 `DataObject` / `FileNameW`。
**格式存在 ≠ 别人读得懂。**

**② 临时目录被拒**（最贵的一个）

```
D:\大脑\表情测试\x.gif       → 彩色占比 10.3%，发出是表情
%TEMP%\bigfish-xxx\x.gif     → 彩色占比 0.0%，什么都没发生
```

**微信拒绝从临时目录粘贴文件。** 而我一直用 `%TEMP%` 造测试图 ——
十几轮都在查功能，其实功能没问题。

**③ 判据用灰度差，5.9 卡在阈值 6 下面**
输入框只有 88px 高，缩略图缩成 48×16 后差值被稀释。
换成**彩色像素占比**：空框 0.00%，有图 10.88%，阈值 2%。

**④ 验证过滤掉了自己发的消息**
`if sender_id != 2: continue`（照抄 vendor）。这台机器上自己发的
`sender_id=4`，于是永远返回 False。

### 真机结果

```
聚焦后 前台='微信' 焦点='微信'
草稿已进输入框（彩色占比 8.5%）
发送后新增 1 条
  · type='动画表情' sender_id=4
✓ 新增消息里有「动画表情」
耗时 9.3s
```

### 教训

**测试环境必须和真实环境同构。**

用 `%TEMP%` 做测试图是很自然的习惯，但它让一个和功能无关的
路径限制变成了「功能不工作」。而我先排查功能、后对齐环境，
白烧了十几轮。

同类错误还有一次：把 `paste_only.py` 报的「⚠ Ctrl+V 没生效」
当成了成功（因为看到输入框里有缩略图，而那是用户之前自己贴的）。

**读日志要读结论那一行，不要读自己希望看到的那一行。**

## 这一轮踩过的、值得单独记的

**`fmtBytes` 重名** —— `stickers.js` 里定义了 `function fmtBytes`，
`app.js` 里已有 `const fmtBytes`。重复声明是 SyntaxError，
**整个 stickers.js 后半段不执行**。表现：页面照常显示，
只有按钮点了没反应。

排查靠 `tools/ui_console.py`（把 console 消息全打出来）。

**`@Slot` 签名写错** —— `@Slot(str, result=str)` 但方法无参。
Qt 找不到匹配的槽，调用静默失败。犯过两次
（`list_memory_sessions`、`sticker_pick_files`）。
后来加了 `tools/check_slots.py` 静态检查。

**`__file__` 是相对路径** —— PyInstaller 打进去的模块，
`os.path.abspath(__file__)` 会按**当前工作目录**解析。
算出来的界面路径取决于用户从哪儿启动 exe。从 `dist/BigFish`
启动时恰好对，换个目录就找不到 `ui/index.html`。
新建 `bigfish/paths.py` 用 `sys._MEIPASS` 做锚点。

**`sticker_dir()` 无条件 makedirs** —— 鲸落删掉数据目录后，
随便一次界面刷新又把空目录建回来，"她不存在了"就不成立。
