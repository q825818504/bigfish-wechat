## 2026-11-03 晚 · 表情包库 + 插件化

### 用户提的需求

> 侧边的表情包，我只希望他这个是表情包库……1、也就是表情包库，里面都是
> 已经存放的表情包；2、添加表情功能，点击之后，弹出一个框，既可以选择从
> 任意来源拖拽，又可以单个或者批量添加，然后自动将任意格式的图片转化为gif
> 保存到表情包库；3、对于每一个表情包要制定一个独一无二的代码，便于发送的
> 时候读取，同时对表情包进行一定的备注，这个备注只有双击表情包库的时候才能
> 显示详细信息……4、对表情包备注功能，要导入的时候大肥鱼自动实现

> 勾选这个启用表情包插件之后，才会在侧边栏有这个表情包板块，
> 也就是表情包所有的功能都在这个表情包插件中

### 关键决定

**表情包是插件，不是内建页面。**

侧边栏那一项跟着插件开关走：关掉插件，入口就消失。
理由：如果插件关着还留着入口，用户点进去只会看到"请先启用插件"，
那是设计上的自相矛盾。

**这一页只管库，不管行为。**

```
表情包页  →  她手里有什么（浏览、添加、改备注、删除）
插件页    →  她要不要发、多久发一次、怎么挑
```

开关和频率搬去了插件配置。混在一起时用户想"关掉表情"得先找到
表情包页，而插件页明明已经有一个开关了 —— 两个开关控制同一件事，
迟早互相打脸。

### 数据结构（schema v2）

```json
{
  "version": 2,
  "seq": 12,
  "items": {
    "stk_0007": {
      "code": "stk_0007",           // 唯一代码，发送时靠它引用
      "file": "stk_0007.gif",
      "brief": "生气",               // 概览：列表显示这一句
      "detail": "眉毛倒竖……",        // 详细：双击才显示
      "tags": ["生气", "愤怒"],
      "source": "import",
      "auto": true,                  // 描述是不是模型生成的
      "frames": 4, "w": 512, "h": 512
    }
  }
}
```

**为什么代码不用语义化前缀**（如 `angry_01`）：语义靠 brief 表达，
而 brief 随时能改。用递增序号最稳，也最短。

**旧格式自动迁移**：v1 的 `{文件名: {desc}}` 在第一次读时转成 v2，
`desc` 放进 `brief`。

### 格式统一转 GIF

微信只把 `.gif` 认成原生表情，所以导入时一律转。

有损，但做了三件事缓解：

1. 尺寸 >1024 等比缩小（微信上限，超过会被当文件发）
2. 调色板用 ADAPTIVE（按实际颜色分布取，不是固定 216 色）
3. 多帧保留（GIF / 动 WebP 逐帧转，动图不会变静图）

透明：GIF 只有 1 位透明，所以 alpha 二值化 —— 半透明边缘会变硬边。
这是格式限制，不是实现问题。

### 自动备注

导入时可以让模型看一眼，填 `brief` + `detail`。

本地网关支持视觉（2026-11-03 实测：发一张红色圆形，返回"红色圆形"）。
图缩到 512 以内再 base64 —— 模型不需要大图，base64 会让请求体涨 33%。

**任何失败都不拒绝导入**：模型挂了、超时、返回格式不对，都退化成
空备注。一张没备注的表情仍然能发（只是插件挑的时候只能靠随机）。

### 学习：主人纠正时改备注

```
主人：这个不是生气，是无语
  ↓
找到最近发的那张（5 分钟内）
  ↓
关键词粗筛 → 模型判断是不是纠正 → 是就改 brief/detail
```

两道门：粗筛省掉 99% 的调用，模型判断挡住"这个表情真好看"这类误伤。

**同步做，不放后台**：放后台的话她这一轮已经用旧理解回复了，
下一轮才改过来，用户会觉得"我说了你怎么还不改"。而粗筛之后
绝大多数消息走不到这里。

**只改最近那张**：翻旧账（"你上个月那个表情用错了"）不处理 ——
分不清指的是哪张，乱改比不改糟。

### 删除：墓碑

Windows 上文件被占用就删不掉（QtWebEngine 预览时持句柄）。
如果整个删除失败，用户点了删除却什么都没变，会以为程序坏了。

所以标记 `deleted: true`：列表跳过、发送读不到，但条目留着，
下次 list 时再试一次真删。

### 踩到的坑

**`sticker_dir()` 无条件 makedirs，把鲸落删掉的目录又建回来了。**

鲸落之后"她不存在"这件事就不成立了 —— 随便一次界面刷新就会
重建空目录。改成纯返回路径，写操作自己调 `ensure_dir()`。

**循环 import**：`stickers.py` 要 `vault`（拿 `resolve_data_root`），
`vault.py` 的转发层又要 `stickers`。只能有一个方向在模块级写。
vault 那边改成函数内 import。

## 2026-11-03 凌晨 · 表情包发送通道

### 关键发现：GIF 文件就是原生表情

微信把剪贴板里的 `.gif` 文件识别成**表情消息**（`local_type 47`），
不是图片。对方收到的是原生表情 —— 能长按添加、会动、进表情面板。

不需要驱动表情面板，不需要破解表情库，不需要「添加到表情」。
只要把 GIF 贴进输入框。

### 真机踩出来的四个坑

**① 剪贴板格式不全**（`CF_HDROP` 不够）

自己拼的 `DROPFILES` 只写出 `CF_HDROP` 一个格式；系统写法有五个。
微信是 Qt 应用，走 OLE，认后者。**格式存在 ≠ 别人读得懂。**

**② 临时目录被拒**（最贵的一个）

```
D:\大脑\表情测试\x.gif       → 彩色占比 10.3%，发出是表情
%TEMP%\bigfish-xxx\x.gif     → 彩色占比 0.0%，什么都没发生
```

**微信拒绝从临时目录粘贴文件。** 而我一直用 `%TEMP%` 造测试图 ——
于是十几轮都在查功能，其实功能没问题。

**③ 判据用灰度差，5.9 卡在阈值 6 下面**

输入框只有 88px 高，缩略图缩成 48×16 后差值被稀释。
换成**彩色像素占比**：空框 0.00%，有图 10.88%，阈值 2%。

**④ 验证过滤掉了自己发的消息**

`if sender_id != 2: continue`（照抄 vendor）。这台机器上自己发的
`sender_id=4`，于是永远返回 False —— 发出去了也记成失败。

### 真机结果

```
聚焦后 前台='微信' 焦点='微信'
草稿已进输入框（彩色占比 8.5%）
发送后新增 1 条
  · type='动画表情' sender_id=4
✓ 新增消息里有「动画表情」
耗时 9.3s
```

### 教训

**测试环境必须和真实环境同构。**

用 `%TEMP%` 做测试图是很自然的习惯，但它让一个和功能无关的
路径限制变成了「功能不工作」。而我先排查功能、后对齐环境，
白烧了十几轮。

同类错误还有一次：把 `paste_only.py` 报的「⚠ Ctrl+V 没生效」
当成了成功（因为看到输入框里有缩略图，而那是用户之前自己贴的），
然后连续五轮在错误前提上改判据、改队列、改顺序、改格式、改聚焦。

**读日志要读结论那一行，不要读自己希望看到的那一行。**
