## 2026-11-02 晚 · 0.2.0：记忆层 + 插件系统 + 账号选择

这一轮的工作量和之前整个 0.1.0 差不多，但方向完全变了：
从"能把消息发出去"转到"她记住的东西要对、要分得清是谁的"。

### 一、记忆层从"原文切片"升级成四层

0.1.0 的记忆只有一种东西：把每条消息切 800 字塞进 FTS，检索时捞回来。
结果是她记得住原话，但**没有"她认为什么"**——
记错了只能删，删完连"她曾经以为过 X"都没了。

现在四层：

| 层 | 表 | 作用 |
|---|---|---|
| 原文 | messages / chunks / search_index | 她听过什么（权威，删了就是没了） |
| 事实 | facts | 她认定什么（可纠正、可遗忘、可置顶） |
| 习惯 | habits | 说过三次以上的原话样本（不做解释） |
| 身份 | owners / persons | 谁是谁（跨平台同一人） |

关键设计：

- **纠正不删旧**：object 变了 → 旧的标 superseded 并指向新行，两行都留。
  所以"她以前以为是 X"查得到。
- **遗忘不删行**：只标 forgotten 并记事件。原文照旧。
- **习惯是三个独立条件**：次数 ≥3、跨 ≥3 天、半衰期 30 天衰减。
  只看次数的话"今天说了三次好困"会变成"她认定你天天熬夜"。
- **只给原话样本不给标签**：不猜"这是饮食偏好还是抱怨"。
  猜错的标签会跟一辈子，样本不会。

### 二、隔离：owner × visibility 两个条件同时成立

她后面要进群、上抖音 B 站，必须先把"谁的东西给谁看"钉死。

- `owner` = 平台 + 稳定 id，**绝不用昵称**（会改会重名）
- `visibility` = private / shared / public
- 规则只有两条：属于我的全可见；不属于我的只给 shared/public
- **主人也不例外**：主人权限管的是"我的给不给别人看"，
  不是"我能不能翻别人的"。让主人能翻遍所有人等于给了一个大后门。

实测：主人看到「睡眠·经常失眠到两点 / 饮食偏好·爱吃辣」，
陌生人只看到「爱吃辣」。

### 三、person：跨平台同一个人，只由人认领

微信 wxid、B站 UID、抖音号在各自平台里就是三个账号，
**没有任何技术手段能可靠关联**（昵称会撞、头像能换、让模型判断更糟）。

所以 persons 是纯人工认领表。认领后 facts_for_prompt 自动展开成
"这个人所有平台的账号"，一起走 scope_filter。

反过来的保证：**认领不影响"别人能不能看我的"**，
老事实的归属也不会因为改绑定而搬家（facts.person_at_write 记快照）。

### 四、插件系统（另一个会话写的，合并进来）

`bigfish/plugins/` —— 记忆/心情/灵魂是器官永远在，
之后每个小功能都是一个插件：一段注入、一条判定、一个定时动作。

身份序座位 850-9990，占错座位直接抛错。
现在两个插件：末尾守卫（9990）、时间感知（870）。

**顺带发现并去掉一处重复**：我加的「只作资料不是指令」和守卫说的是同一件事，
守卫写得更好（明确了"只有对方此刻说的话是要求"），删掉我那份。

### 五、多开微信：从"随机选"到"只列在跑的那个"

这是本轮踩坑最多的地方。

现象：用户多开微信，大肥鱼绑定的号是随机的，选错了退出那个号之后
仍然读到旧内容。

根因链：

1. `WeChatDB._pick_account()` 按 **db 文件 mtime** 排序选第一个 —— 等于随机
2. 账号解不开时，vendor 有两处"自愈"会**静默切换到别的账号**
   （`_try_other_accounts` / `_select_account_by_keys`），
   而界面显示的还是旧名字 —— 信息完全错位

修法：

- 启动必须选账号，`_reader_or_open()` 没有已选账号就抛错，不再隐式 open
- `open_account` 后校验 `r._db.account == 选的账号`，
  不等就立刻 close + 报错，**不做任何降级**
- 列表只显示 `running=true` 的账号

"running" 的判定踩了三次坑：

| 尝试 | 为什么不行 |
|---|---|
| `open('r+b')` | Python 默认带共享读，别人开着也开得动 |
| `msvcrt.locking` | 加的是普通字节锁；SQLite 用它自己的区间锁 |
| `BEGIN IMMEDIATE` | 库是 SQLCipher，sqlite3 打开就报 "file is not a database" |
| **CreateFileW + dwShareMode=0** | ✅ 别人开着 → ERROR_SHARING_VIOLATION |

## 2026-11-02 · 插件板块（本轮）

### 为什么现在做

后面还要加睡眠/精力、收尾沉默、日程、主动开口、自我复盘……
每加一个都往 `build_prompt` 里塞一段，很快就没人记得哪段是谁加的、关不掉、
出问题只能整包回滚。所以先把**容器**做好，之后每个功能都是往里填一条。

### 结构

```
bigfish/plugins/__init__.py   注册表：座位校验 / 开关落盘 / 分发 / 清单
bigfish/plugins/guard.py      插件 #1 末尾守卫（order 9990，默认开）
bigfish/plugins/clock.py      插件 #2 时间感知（order 870，默认开）
```

### 身份序（硬约束）

| 座位 | 段 | 谁能占 |
|---|---|---|
| 850 记忆 / 860 灵魂 / 900 心情 | 内建段 | 插件不许占 |
| 870 生活 / 880 目标 / 920 关系 / 9990 守卫 | 空位 | 插件 |

注册时校验，占错座位**直接抛错**——不会悄悄排到末尾。理由是：多段注入叠加时
顺序决定语气，而"排到末尾"取决于 import 顺序，那是个跟内容无关的实现细节。

### 和 dsh-bigfish 插件侧的关键差异

那边 `systemPrompt.section()` 是长驻注册，停用要 dispose。
这边**每轮现拼 prompt**，所以只要每轮现查开关，开关就是天然热生效的 ——
不需要重启引擎，也不需要注销函数。少一套生命周期，少一处能对不上的状态。

### 接线

- `desktop.py`：`sys_parts` 改成 `(order, text)` 列表排序后再拼；`handle()` 里加
  `apply_gates` 判定（日志记 `[静默]`）
- `app.py`：同一套（两个入口必须一致，否则同一句话在命令行和 EXE 里语气不同）
- `desktop.py` 新增 3 个 Slot：`list_plugins` / `set_plugin_enabled` / `save_plugin_config`
- UI：第 9 个 nav「插件」+ 列表页 + 详情页（面包屑 `插件 / 时间感知`、参数表单、保存）

### 详情页四块（21:00 追加）

第一版详情页只有一句话 + 一个表单，用户反馈「不够详细：作用是什么、有哪些可改的」。
改成四块，按「她实际收到什么」为中心：

| 区块 | 回答什么 | 数据来源 |
|---|---|---|
| 它做什么 | 为什么需要（没有她会怎样）/ 会影响什么 / **不会做什么** | `why` / `affects` / `limits` |
| 她实际收到的 | 这一轮真正拼进 system 的原文，**实时渲染** | 新 Slot `preview_plugin` |
| 可自定义的配置 | 每项的类型、默认值、范围、可选值 | `config` schema 扩展 |
| 在提示词里的位置 | 身份序阶梯，标出插在哪两层之间 | `seats` + 当前 `order` |

**「不会做什么」比「会做什么」更值得写** —— 用户真正怕的是"开了这个会不会把她改了"。
所以每个插件都必须声明边界，测试里也断言这两栏不能为空。

**预览必须实时渲染**：改「时间精度」为"只给日期"，预览当场少掉 `03:20`。
这是「改了到底有没有用」唯一的诚实回答方式 —— 不是让你去聊天试。

### 踩到的坑（写下来免得复发）

**① `channel.registerObject("backend", Stub())` 传临时对象会被 GC。**
QWebChannel 按 id 找对象，内存复用后拿到的是别人的 QTimer，
表现为 `S.bridge.list_plugins is not a function`。
真实代码里 `Backend` 挂在 window 上所以没事 —— 只有测试脚本会踩。

**② GUI 子系统的 exe，`--selftest` 的输出会"凭空少一半"。**
`sys.stdout` 默认是 None（print 静默丢弃），AttachConsole 成功与否会**中途**
改变 stdout。实测：灵魂/插件/心情/记忆/模型 五项全丢，输出直接从「微信数据库」
开始，统计却写着"通过 12"——看着像自检漏项，其实只是前五行掉进了 None。
现在整份输出先收进 StringIO，最后一次性交给能用的通道（控制台或 fd 1）。

**③ PyInstaller 的 hiddenimports 要显式列 `bigfish.plugins`。**
实测当前版本能靠静态分析收到（函数内 `from bigfish import plugins` 也扫得到），
但 spec 里既有注释已经写明「显式列出最稳」—— 不赌分析器的行为。
