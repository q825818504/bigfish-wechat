## D-1 放弃 hook 路线

**时间**：2026-11-01 上午

**背景**：最初计划用 `version.dll` 注入让微信暴露更多能力。

**证据**：
- 小号装好后约 10 分钟内被封
- hook 要改客户端文件（签名变 `HashMismatch`）
- 要往进程里塞自制 DLL 并长期驻留
- 为了不被发现还要隐藏模块（`HideModuleFromPEB`）

**决定**：放弃。

**理由**：本质是改客户端，服务端看得见。风险不可控。

## D-2 选择 wechatauto-replica 而不是自研

**时间**：2026-11-01 中午

**背景**：需要读微信数据库。

**证据**：
- 上游 581 star、254 fork、Apache-2.0
- 561 项离线自测
- 每个 bug 修复都附三轮真机复现 + 数据库回读对照
- 作者会明确写「未测，如实说明」

**决定**：用上游，本地改造。

**理由**：数据库解密（SQLCipher 4 + WAL 合并 + 页验证）这块自己写风险太大。

## D-3 微信版本锁 4.1.15.53

**时间**：2026-11-01 下午

**背景**：原用 4.1.10.27（为配合 hook 降级）。

**证据**：
- 4.1.10.27 不在上游版本表里
- 动态扫描出的 3 个候选逐个热写，树全部没物化
- 静态分析（capstone + numpy）找到 0 处字符串引用
- 升级到 4.1.15.53 后 gate `0x0B3959D8` 一次成功

**决定**：锁 4.1.15.53。

**理由**：UIA 热激活依赖精确的 gate RVA，4.1.10.27 的实现差异太大。
hook 路线已死，降级理由消失。

## D-4 密钥提取走管理员桥

**时间**：2026-11-01 下午

**证据**：
- 普通权限 `OpenProcess(PROCESS_VM_READ)` → `err=5 ACCESS_DENIED`
- 管理员权限 → 全部 OK
- 实测多次确认

**决定**：不做整体提权，只在取密钥时启动短命管理员子进程。

**理由**：
- 发送路径（GUI）在提权会话里容易出问题
- 拖拽文件、写普通用户目录会变麻烦
- 权限面越小越好

**实现**：`_bigfish_keybridge.py`，子进程返回的密钥仍逐个过页1 HMAC 校验。

## D-5 界面用 QWebEngine 而不是 Qt 原生控件

**时间**：2026-11-01 傍晚

**证据**：
- WeChatAgent 自己就是 Chromium + HTML
- `dsh-bigfish/client.js` 的记忆星空是纯 web 代码（Canvas + SVG）
- Qt 原生控件做不出玻璃质感、多标签动效

**决定**：HTML 界面 + QWebChannel。

**代价**：安装包 +150MB（Chromium 内核 195MB）。

**理由**：界面要能直接复用插件视觉，以后改界面不用碰 Python。

## D-6 安装器自己写，不用 Inno Setup

**时间**：2026-11-01 傍晚

**证据**：
- Inno Setup 装不上：写 `%TEMP%` 报 `Error 5: 拒绝访问`
- 换自定义目录后挂起在无界面弹窗，5 分钟无进展

**决定**：用 PyInstaller 打一个安装器，安装逻辑自己写。

**实现**：解压 zip → 建快捷方式 → 写注册表卸载项 → 启动程序。

**注意**：用 onedir 而不是 onefile，因为 onefile 每次运行要解压自身到
`%TEMP%`，受限环境会报 `Could not create temporary directory!`。

## D-7 群聊默认只在被 @ 时回

**时间**：2026-11-01 傍晚

**证据**：
- 活跃群一天几百上千条
- 全回等于刷屏，而且微信会把你当机器人

**决定**：三层判据（`\x01` 占位符 → 群成员表 → 昵称精确匹配）。

**理由**：`@` 后面是群昵称不是 wxid，昵称会重名会改，不能只靠字符串匹配。

## D-8 回环防护加四层

**时间**：2026-11-01 晚上

**背景**：实测发生自问自答，手机端收到刷屏。

**证据**（真实对话）：
```
[对方 155] '在吗'
[我 4]     '在，爸。'          ← 回复被读回来
[我 4]     '嘿，你把我话抄回去了？'  ← 又触发
[我 4]     '哈，还真抄回去了...'
（持续到手动终止）
```

**决定**：四层防护。

| 层 | 机制 |
|---|---|
| 1 | `allow_self` 默认 False |
| 2 | 内容比对（20 秒窗口，归一化后比较） |
| 3 | 归一化剥掉 `wxid_xxx:` 和 `@昵称` |
| 4 | 频率熔断（90 秒 4 条） |

**第 3 层是测出来的**：第一版没剥 `@` 前缀，测试用例直接暴露。

## D-9 水位不跨进程持久化

**时间**：2026-11-01 下午

**证据**：
- `get_new_messages` 是 `ORDER BY sort_seq ASC LIMIT n`，返回**最老**的 n 条
- 水位从 0 开始时永远追不到最新
- 残留的水位文件曾把新消息挡在外面

**决定**：
- 不用 `get_new_messages`，改用 `get_messages` 降序取最新 + 水位比较
- 水位不落盘，每次启动重新对齐

**理由**：宁可重启后漏掉关闭期间的消息，也不要「发了但监听不到」。
