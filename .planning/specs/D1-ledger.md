# D-1 共同账本（我到底发过什么）

> 规格定稿：2026-11-05
> 状态：**已实施**（2026-11-05）
> 上游：A-1 已能说出"拿不准"。D 要回答另一个问题：**"但我 3 秒前发过这句。"**

---

## 一、要解决什么

现在"我发出去的东西"有两套互不认识的记录：

| 位置 | 记什么 | 用在哪 |
| --- | --- | --- |
| `loopguard._sent` | 文本 + 时间戳（**全局，不分会话**） | 拦截回环 |
| `app.py` 发送确认 | 去库里查 `is_self` 新行 | 判断"我那句话入库没有" |

而且 `loopguard` 的账本只有 `desktop` 引擎有一份，`app.py` 完全没有。

A-1 做完之后局面变了：**A 能说"是我发的"了，账本剩下的价值不在"再确认一遍"，而在否决 A。**

那晚真正缺的就是这一环：A 判成"对方说的"，然后就没有任何东西能把它按住。

---

## 二、决定（来自 4 轮问答）

| # | 决定 |
| --- | --- |
| 1 | 账本同时负责**拦截**和**发送确认**（两套记录合并成一套） |
| 2 | **不持久化**，进程重启即清空（与 D-9 水位同一理由：残留值会误杀） |
| 3 | 匹配标准：**相等**，或**长度差 ≤ 10% 且前 12 字相同** |
| 4 | **账本可以否决 A**，但只在 A 说"对方"时；每次否决必须留痕 |

### 2.4 为什么允许否决

否决是这次唯一新增的"权力"。给它的理由：

- 那晚 A 判错了，错在没有第二道；
- 否决的失败代价 = 吞掉一条真消息（对方复述她的原话，且 90 秒内）；
- 不自环的失败代价 = 刷屏 + 记忆污染 + 只能杀进程。

两者差一个量级，所以允许，但**必须留痕**，否则它会变成新的"改了没生效"。

---

## 三、模型

```python
@dataclass(frozen=True)
class Entry:
    chat: str        # 会话 id（空 = 不分会话，兼容旧调用）
    text: str        # 原文
    norm: str        # 归一化（空白折叠、去首尾）
    at: float        # 记账时刻
    local_id: int    # 发送确认后回填；0 = 未知
    epoch: int       # 进程代次，用来表达"重启即失效"
```

### 3.1 操作

| 方法 | 语义 |
| --- | --- |
| `note_sent(chat, text)` | **发送之前**记一笔，返回句柄（用于回滚/确认） |
| `rollback(handle)` | 发失败撤账（否则会误杀对方复述） |
| `confirm(handle, local_id)` | 发送确认后回填库里那一行的 id |
| `lookup(chat, text)` | 找"这句我发过吗"，返回 `Entry` 或 `None` |
| `prune(now)` | 按窗口裁旧 |
| `snapshot()` | 调试用 |

### 3.2 匹配

```
归一化：去首尾空白、把连续空白折叠成一个空格
命中条件（两条任一）：
  a) norm 完全相等
  b) 长度差 / 较长者 ≤ 0.10  且  norm[:12] 相等
```

`b` 是为了容纳微信可能做的改写（前后加空格、换行变空格），
但**长度差 10% 这条把"对方复述一整段"挡在外面** —— 那正是 D-20 的坑。

### 3.3 窗口

默认 **90 秒**（`echo_window` 现在只有 12 秒，挡不住缓冲/慢网络）。
可配：`ledger.window_seconds`。

条目上限 200 条 / 会话，防止长会话无限增长。

## 四、否决规则

```
if A 说 peer:
    hit = ledger.lookup(chat, text)
    if hit and (now - hit.at) <= window:
        → 改判 self，规则码 ledger_veto
        → 写证据链（identity_trace），decision.reason = "ledger_veto"
```

- 否决后**不回复**，行为等同 SELF 且 `allow_self=False`。
- 否决**必须**进证据链；没进就等于这条改动白做。
- A 说 unknown 时不动（unknown 的处理策略已经足够保守）。

## 六、验收

1. `note_sent` 后 `lookup` 命中（同会话）
2. 别的会话查不到（会话隔离）
3. 精确相等命中
4. 长度差 > 10% 的前缀**不**命中（防复述）
5. 长度差 ≤ 10% 且前 12 字相同 → 命中（容改写）
6. `rollback` 之后查不到
7. `prune` 之后超出窗口的查不到
8. `confirm` 回填 local_id
9. `lookup` 不修改账本、不产生副作用
10. 条数上限生效，最旧的被丢
11. 归一化：多余空白、首尾空白不影响命中
12. 空文本不记账
13. LoopGuard 用外部账本时，`is_echo` 走账本
14. LoopGuard 不给账本时行为与现在一致（向后兼容）
15. 否决：A 说 peer + 账本命中 → 改判 self
16. 否决：A 说 peer + 账本未命中 → 保持 peer
17. 否决：窗口外不否决
18. 否决必须留痕（证据链里能看到 `ledger_veto`）

---

## 七、明确不做

- 不落盘、不跨进程（D-9 的教训）
- 不按文本相似度做模糊匹配（D-20 的教训）
- 不让账本否决 `unknown`（unknown 已经足够保守）
- 不把账本写进 vault（它是可丢的运行态，不是记忆）

### 实施时改掉的两条规则

**① 前缀匹配从"互相前缀"改成"相等 + 紧前缀"**

原测试 `长文本前缀命中 → echo` 用 16 字对 22 字（多 7 字）断言"命中"。
新规则下不成立——**读回来不可能凭空多出七个字**，多出来就是另一条消息。
旧断言编码的正是 D-20 要拆的那条线，已改成"原样读回命中 / 多出字不命中"。

**② 长度容差加了绝对下限**

纯比例算 10% 时，7 个字差 1 个就是 14%，会被判成两句。
改成 `差 ≤ max(1, 10%)`，并且**短句不比前缀**（少于 12 字时前缀没有区分力，
拿它当依据只会误杀）。
