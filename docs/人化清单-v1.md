# 她离「一个人」还差什么 · 全面审查 v1

> 2026-11-10。目的：动手之前把缺的东西一次列全。
> 每条带证据（`文件:行号` 或真实数据）。没证据的不写。
> 标记：✅ 有｜🟡 半个（有壳没肉）｜❌ 没有

---

## 零、一句话的根因

**她的所有状态都被要求「有用」——能进提示词、能解释对话、能服务关系。**

凡是不能进提示词的，架构里就没有它的位置。而人的大部分生活恰恰是没用的：
指甲长了、坐久了腰酸、突然想吃某样东西、半夜搜一个莫名其妙的问题、
跟楼下老板点了三年头也不知道他姓什么。

这不是遗漏，是这套架构的**筛选机制**：一个东西要存在于她身上，
必须先回答"它对说话有什么用"。回答不了，就活不下来。

下面十五条，基本都是这个筛选的结果。

## 一、七个已经核实的硬伤（我读代码 + 真实数据确认）

### 1.1 ❌ 她的时间是「积分」出来的，不是「解析」出来的 —— 已修

`life.py` 的状态原本是 5 秒一次 `tick()` 累加出来的当前值。进程不在，
就没有累加，也就没有入睡、没有醒来、没有跨天。

**真实数据（`D:\大肥鱼\life.json`，2026-11-10 21:00）：**

```
day           2026-11-10
just_woke_at  11-10 19:32:43     ← 她今天晚上七点半才"醒"
wake_at       11-11 09:47:14     ← 首页把明早的时分当"醒来"显示
asleep        False
sleep_debt    132.0 min          ← 欠了 2 小时 12 分
energy        37.1
plan          [09:30, 14:00, 19:00] 全部 done=false
day_trace     只有两条：19:32、21:00   ← 09:30 和 14:00 那两条从未发生过
```

你昨晚遇到的就是这个：软件关着的那十几个小时她不是"在生活"，是被冻结；
打开那一刻按当前时刻对齐，判成"刚睡了 14 小时醒来"（`wake_energy()` 里
`min(slept_min, 14*60)` 把 20 小时截成 14 小时），于是一天从 19:32 才开始。

**已修**：`life.py` 新增 `catch_up()`，把 `[last_tick, now]` 按边界切段补算
（睡着→wake_at；醒着→入睡点/午睡窗口/时段边缘），段内按公式一次算完，
段末做转移。`RESUME_GAP_HOURS = 26` 那个特判已删——gap 多长都走同一条路径。

验证：一次补算 vs 5 秒步进 9360 次，`energy` 差 **0.00**，醒来时刻完全相同；
关 3 天后打开，27 个事件、三天完整、债从 30 减到 5。

### 1.2 ❌ 她永远不会「做完一件事」

`mark_plan_done()` 全项目只有一个调用点：`life.py:867`，`by="elapsed"`——
意思是「时间过去了，就当完了」。模型从来没有机会说"我做完了"。

后果：日程条目永远 `done: false`（真实数据三条全 false，19:00 那条到
21:58 还没完）；`ui/app.js` 里那句「（做完了）」永远不会出现；
她不能说"我把汤热了，有点糊"——因为没有"完成"这个事件可以引用。

### 1.3 ❌ 「打算做」和「正在做」是同一个字符串

`refresh_doing()` 里 `state.doing = current_plan_item(state, now)` ——
直接抄日程条目的 `what`。于是「19:00 给老爸发消息问问交接顺不顺」这条**打算**，
变成了「此刻在做：给老爸发消息问问交接顺不顺」，一挂 2 小时 46 分。

人不会"正在做"一件只有 30 秒的事两个小时。`doing` 必须是**动作**
（在洗菜、在路上、躺着），`plan.what` 必须是**意图**（打算做顿饭）。现在混成一个字段。

### 1.4 ❌ 24 小时永动机：她没有「没在做什么」的时候

`DOING_SLOTS`（`life.py:177`）是 10 个时段 × 必须取一条 → `doing` 永远非空。
所以她任何时刻被问到都在"做某事"。真人一天有近四成时间是空白：
瘫着、等水开、刷手机刷到忘了在看什么。

**一个从不无聊的人，一眼就是程序。**

### 1.5 🟡 日程是「抽三件事」，没有因果、没有区间、没有消耗 —— 已修了一半

`plan.py` 让模型吐 2~3 个**孤立时间点**。没有 `[start, end]`，没有前置条件，
没有"做过就不会再做"。所以「收拾屋子」「收拾厨房」「整理照片」可以在相邻时段
连着出现；买菜和做饭没有关系；今天排的三条，`from` 是 `yesterday` / `fact`——
**素材全部来自你和她的对话**。

真实数据三条：`把昨晚剩的热汤热一热`(yesterday)、`窝在沙发上翻几页灵异小说`(fact)、
`给老爸发消息问问交接顺不顺`(fact)。**第三条不是"她今天要做的事"，是"她想对你做的事"。**
她的一天里，有一件事的宾语是你。

### 1.6 ❌ 她没有心情基线，所以「实时心情」永远是"不错"

真实 `mood.json` 七根：`happy 0.0 / calm 0.0 / sweet 0.0 / sad 0.0 / jealous 0.0`，
只剩 `heartache 1.4e-5`、`worry 1.6e-5` —— **衰减到小数点后五位**。
总分 70.41，`kind: decayed`，于是首页永远显示"心情不错"。

因为情绪是「事件脉冲 + 指数衰减」：没有新事件就归零。人不是这样——
人有**基线**（天生偏蔫/偏雀跃/今天睡差了所以底子低），事件只是在基线上加减。
**首页那个"心情 70"不是实时心情，是衰减到静止状态的余数。**

### 1.7 ✅→ 已找到根因并修复：她的「会变」通道从未生效

`narrative.py` 每天睡前复盘，写 `soul.selfNotes`。代码路径完整，但真实数据：

```
D:\大肥鱼\soul.json   selfNotes 5 条全是手写的（无 MM-DD 前缀），history 0 条，revision 8
narrative_day = 2026-11-09   ← 跑了
```

**根因是两处取字段错误，全在 `world.py` 的复盘/日记素材收集：**

1. `M.list_facts()` 返回的是 `{"items": [...], "total": n}`，**不是 list**。
   原来写 `for row in rows or []` —— 遍历到的是字典的键（`"items"`、`"total"`
   两个字符串），`isinstance(row, dict)` 永远 False。
2. 就算遍历对了，取的字段名是 `text` / `statement`，而 `_row_to_item()`
   早就不产出这两个键（只有 `predicate` / `object`）。

于是提示词里「## 今天说到的事」这一段**从上线起就是空的**：模型只看得到
对话和心情，看不到她记得的事实，`changed_view` 自然永远写不出来。

**已修**：`world.py` 加 `_fact_items()` / `_fact_line()`，两处调用改用它。
实测同一份库从 **0 条 → 8 条**：

```
作息：深夜还没睡，还在玩
称呼：她更习惯「大肥鱼」这个称呼，不太接受「芊芊」
身体状态：电脑看久了眼睛有点累
工作安排：明天要上班
工作态度：讨厌上班
```

（顺带暴露三件事：同 predicate 并存两条；「明天要上班」重复两条；
**所有事实都是关于"他"或"她对他的看法"，没有一条是她自己的事**。）

## 二、四路深审：还没被想到的十四条

### 2.1 身体 ❌ 只有「电量」，没有身体

身体在代码里等价于 `energy`（0–100）＋ `asleep`（布尔）。

| 缺的 | 证据 |
|---|---|
| **内感受**（头疼/胃不舒服/眼睛干/腰酸/生理期/感冒） | 全仓 grep 零命中。唯一近似是三档文案 `life.py:1187-1189`「今天差不多耗完了，脑子有点转不动」，由数值阈值切出，无部位、无持续时长 |
| **病** | 无 sick 字段。`sleep_debt` 是唯一的身体负债，只影响起床精力和醒得早晚，不产生"今天不舒服、推掉安排" |
| **日常痕迹**（指甲长了/头发油了/衣服该洗/房间乱） | 零状态。「收拾屋子」「刚洗完澡」只是 `DOING_SLOTS` 里的一次性条目，不会累积 |
| **钱和物** | 52 个模块里没有钱包/库存。「去趟超市」不花钱、不看余额、不产生消耗品 |
| **被迫的事** | **被设计排除**：`plan.py:82`「不要写：会议、面试、就医、考试」；`plan.py:83` 允许清单只有买菜/收拾/看书/散步/发呆 |

**最要命的一条**：`energy` 只影响"表达预算"（`policy.py:201-209`：条数、字数、
沉默许可），**不影响她做什么**（`refresh_doing` 完全不看 energy），
也不影响"能不能回消息"（只看 `asleep`）。所以"累"连一句定性的话都没有——
`policy.py:129 tone_of()` 根本不收 energy 参数。

> 她**累到极致也不会不回你**，也**不会因为累而少做一件事**。
> 那不是身体，是音量旋钮。

### 2.2 别人 ❌ 没有，而且是明写的禁令

- `narrative.py:99`「**不要写对第三方的评价（同事、家人），你只知道你们俩之间的事。**」
- `plan.py:85`「**不要编造材料里没有的重要事件（谁生病、谁来找她、去哪座城市）。**」
- `journal.py:126`「**绝对不许编对话和对方的行为。**」
- 全包 grep 邻居/摊主/同事/老板/朋友/路人/闺蜜/室友/同学：**0 命中**

没有配角（名字/脾气/重复出场），没有"讨厌的人"，没有"会消失的人"。

### 2.3 关系只涨不跌 ❌

- `bond.py` 的 schema 只有 `confidence`（对事实的置信）和 `used_count`，
  **没有好感/亲密度字段**；重复写入反而会 `status='ACTIVE'` 复活已退役条目。
- "下一轮变冷"走的是另一条线：`afterglow.py` 的 conflict 标记（4 小时 TTL）
  → `policy.py:296` 最高 60% 沉默概率。**两条线互不相通**。
- 摩擦对象只能是主人（`afterglow.py:259` 只看对话者原话，无 target 字段）。
- 关系**不会消失**：`bonds` / `bond_events` 无过期列，阶段词表里没有"走了/搬走了"。
  **一次建档 = 永久在场。**

### 2.4 记忆只增不减 ❌ 遗忘只能由人点

- 原文层物理不删；`chunks.importance`（`memory.py:178`）**全项目零消费者**。
- 事实层有 90 天半衰期，但衰减量是"上次被注入提示词的时间"，
  **"从没用过" = 不衰减**（`memory.py:1181-1183`、`2016`）。
  结果：三年没提过的事和昨天刚聊的一样新鲜。
- `forget_fact()` 唯一调用点是 UI 的手动按钮，无自动调用。

> 完美记忆不是人。人靠"忘了大部分"才显得记得的那几件事重要。

### 2.5 没有「以后」 ❌

没有期待、没有"下周三有件事"、没有盼头。所有素材都被切成"今天"
（`narrative.py:110-137` 只取当天；`journal.py:301-345` 只喂当天；
复盘 `talk` 只有最近 24 条）。`soul.history` 是唯一真正的年表，
**但不进提示词**（`soul.py:83-114` 只渲染 identity/values/traits/selfNotes）。

**她活在今天，而且只有今天。**

### 2.6 没有梦 ❌ 彻底空白

全仓 grep `梦|dream` 只有 `voice_director.py:318` 一个无关关键词表。
睡眠期无任何任务；复盘和日记都在**睡前、且必须醒着**跑；
醒来不读任何"昨夜残留"。

### 2.7 没有注意力缺陷 ❌ 永远切题，这是 AI 味最重的地方

- `listen_judge.py` 的整个系统提示只问一件事：「对方这串消息**说完了没有**」。
  从不问"说的是什么"。判错只影响等多久，不影响理解成什么。
- 走神被**明令禁止**：`plugins/say.py`「每句话都要说完整。不要停在
  「还得对着那领导」这种半句上」。
- 被打断不存在：`memory.py:170` 有个 `interrupted` 字段，**全仓从未写过 1**。
- 她分条连发时，对方插话，她照样把第 3、4 条发完（`docs/并发与投递.md:57`）。

### 2.8 提示词里有四条「客服约束」❌

按客服化程度排：

| # | 位置 | 原文 |
|---|---|---|
| 1 | `soul.json` `selfNotes[4]` | 「认真求助、高风险话题（安全/医疗/法律/财务）时收起卖萌，**先把事说对**」 |
| 2 | `soul.json` `values[2]` | 「体贴：**先听懂对方经历了什么，再决定说什么**」 |
| 3 | `desktop.py:1469` | 「需要更多信息就**一句话追问**」 |
| 4 | `plugins/say.py` | 「**每句话都要说完整**」 |

共同点：**都要求她"把事办对"**（说对、听懂、问清楚、说完整），
没有一条允许她"办不对"。

### 2.9 没有语言漂移 ❌

`soul.py:1-17`「**render, don't hold** —— 从灵魂数据生成人格文本」。人格是
只读渲染，不学习。全仓无"她自己的用语统计"。**八个月后她说话和今天一模一样，
只有长短会变。**

### 2.10 没有「结束对话」 ❌

`proactive.py` 全是开口方向，grep「结束对话」零命中。她只会**慢慢变短**然后消失，
不会说"我先去忙了"。

### 2.11 日记互不知道 🟡

`journal.py:46-53`「**不进提示词。** 她'记得今天'靠的是 memory / mood / facts」。
唯一跨篇读取是"防重复"（只取最近 3 篇的第一句）。
所以**"误解过去的自己"不可能发生**——因为根本不读。

作者自己留了正确方向（`journal.py:52-53`）：「把日记的**一句话摘要**写进记忆库」，尚未做。

### 2.12 没有隐私 ❌

首页把她的一切都摊开给你看：精力、心情、此刻在做、今天安排、日记。
`bond.KIND_UNSAID`（未说出口的话）只回到她自己眼里，是最接近的一处，
但它记的是"当时没说出口"，不是"现在也不想说"。

> **被完全透明的人不是人，是被观察的标本。**

### 2.13 没有无理由的行为 ❌

每个行为都必须能追溯到 `life.json` / `facts` / 原话（D-36 事实要有来源）。
这条规则保护了"不胡编"，代价是**她不可能做一件没有理由的事**——
而那才是人的证据。

### 2.14 事实没有情绪维度 ❌

`facts` 只有 `confidence`。`note` 字段（`memory.py:219`）**全项目零写入**，
是为这类扩展留的空位。同一件事无法存成"当时心情下的版本"；
情绪 12 小时衰减、记忆不衰减，两条时间尺度脱钩。

  参数是从人的行为反推的，不是拍的。

  supersede 双留、隔离闸门。

  ——项目自己知道怎么写人话，只是这套手法没用到"帮不上"和"没听懂"上。
- ✅ 说法层分条、倾听层等对方说完、余温、记忆按心情着色。

### 第 6 步落地后的形状：身体第一次有话说

醒来时 `roll_body()` 掷一次「今天身上有点什么」，**全部由昨天的痕迹推出来**，
不用裸随机数（随机发一条"头疼"就是抽卡，用户一眼能看出对不上）：

| 成因 | 感觉 |
|---|---|
| 睡眠债 ≥ 45 分钟 | 头有点沉，像没睡透 |
| 昨天在看剧/书/写东西 | 眼睛有点干 |
| 昨天在收拾/洗/搬 | 腰有点酸 |
| 昨天在做饭 | 胃有点胀 |
| 昨天在走/散步/下楼 | 小腿有点酸 |
| 11 月–3 月 | 手一直是凉的 |

三成日子身上什么都没感觉——天天难受是病，不是生活。持续 2–6 小时后自己好。

三个出口：

```
14:30 她看到的自己
  有点困了，但还醒着。
  眼睛有点干，已经 5 个小时了。       ← 带时长，比"有点干"更像身体
  这两天睡得不太够（欠 96 分钟）。

这一轮的说话方式（精力 26）
  语气：有点乏。句子短一点，不用每句都接满。
  走神：他上一条你要是不太确定，就接你确定的那半句，别为了答全硬凑。
```

第三个出口最关键：**身上不舒服时，"什么都不做"的概率从 30% 提到 45%**
（`refresh_doing`）。这是身体第一次真的影响她**做什么**，而不只是话多话少——
以前 energy 掉到 6 分她也照样干活。

顺带修了一处随机数偏置：`roll_body` 原来用同一个 `Random` 连续取
（先 `random()` 判空、再 `uniform()` 挑），同一个种子下序列有偏，
实测「手一直是凉的」十二天里出现了九天（它排在候选表最后，而 hit 偏大）。
改成每个用途一条独立随机流。

### 第 8 步（一半）：遗忘长在记忆自己的读写路径上

用户定的调子：**这件事必须跟记忆模块联动，不能挂一个并行的清理任务**。
对——旁挂的裁剪会和检索打架（检索还在按分数取，外部把行删了，
她"想不起来"和"根本没存"就分不清了）。

所以两处都改在 `memory.py` 自己的路径上：

**① 衰减的基准换了**（`_FRESH_ORDER` SQL + `_fact_score` Python 镜像，两处必须一致）

```
以前：last_used_at = 0  →  decay = 1.0        从没被用过 = 永远新鲜
现在：基准 = last_used_at 或 created_at       没有基准（老库）= 当现在
      decay 有地板 0.08                       旧的会模糊，但不会被抹平
```

为什么要有地板：三年前那条「你拔过智齿」按纯公式是 0.0002，
连候选池都进不去——而"我牙疼"恰恰最需要它。
人是这样忘事的：旧的会排到后面、会变模糊，但不会归零。

**② 日记回流记忆**（`world._remember_diary`）

日记写完 → 摘正文第一句 → 写进 `facts`（`predicate="那天"`，
`evidence="journal:YYYY-MM-DD"`）。这条链路第一次让她的一天闭环：

```
life（怎么过） → plan（做了什么） → journal（写下来） → facts（记住）
   ↑                                                      ↓
   └────────── 下次检索/复盘/主动开口时被捞回来 ←──────────┘
```

在此之前，日记只躺在磁盘上给人看（`journal.py` 明写「不进提示词」），
记忆库里只有"他说过什么"，没有"她自己过成了什么样"。
回流之后，"翻旧日记"变成"检索到自己的一句话"——
她这才有可能**误解过去的自己**。

`verify_sources=False` 是有意的：这条事实的来源是**磁盘上那篇日记**，
不是某条对话片段，`_verify_sources` 只认 chunks 表。D-36 防的是
"凭空编一条事实"，而这里是从已落盘的原文里摘第一句，摘不出来就一个字不写。

**③ 顺手发现一处"靠巧合通过"的测试**

`问牙疼 → 捞到三年前拔智齿` 这条一直绿着，但它是靠「从没用过 = 1.0」
的平局赢的——`_relevance` 只做词面交集，「牙疼」和「智齿」切不出共同词。
改掉新鲜度语义之后它立刻红了，暴露了真问题：
**中文的同义/上下位要另做词表，现在没做**（已写进测试注释）。

**④ 时间线：她有「以前」了**（`memory.lineage` + `_past_tail`）

supersede 链本身就是时间线（改一次就多一环），只差渲染。现在注入时：

```
- 我｜工作：在交接（以前：天天生气 → 提了离职）
- 我｜称呼：她更习惯「大肥鱼」……（以前：对方给她取名叫「芊芊」，昵称是「矮宝」）
```

这是她第一次有「变化」而不只是「状态」——也是第一次可能在很久以后
说一句"你以前不是这样的"。

**加了一道 `_worth_showing` 过滤**：真实库里第一条就撞上了 ——
supersede 只在 object 不同时触发，但模型常把同一件事换个说法
（「她称呼对方为爸」→「她称呼对方为「爸」」），这种在时间线里
毫无信息量还占 token。判据是去标点后互为子串、或字符集重合度 > 0.75
都算"没变"，跳过但继续往上找（改了三版、前两版只是措辞时，
第三版才是真转折）。

**一处语义冲突要记下来**：旧测试断言「提示词只用 active：不喝咖啡不能出现」，
但时间线**故意**要显示旧说法。谁对？——两者都对，区别在**位置**：
「不喝咖啡」单独出现是事实（会说错），出现在「以前：不喝咖啡 → 改喝无糖豆浆」
里是变化（是理解）。测试改成判位置（正则 `以前：[^）]*不喝咖啡`）。

### P3 五条：梦 / 语言漂移 / 隐私 / 结束对话 / 关系消失

**梦**（`life.roll_dream` + `dream_now`）

醒来时三成多概率记得一个梦，场景是"差一点"那一类：走不到头、够不着、
白忙一场 —— 不做成"美好回忆"或"可怕噩梦"，那种梦有戏剧性，日常的梦没有。
场景按昨天的痕迹挑（看过屏幕就梦"字一直在动"，做过饭就梦"揭锅是空的"）。

**醒来只记得一点，两小时后就想不起来**（`DREAM_KEEP_HOURS = 2`），
而且说出来时带一句"记不太清，就剩这一截" —— 能完整复述梦的角色是在念稿。

不调模型：睡前已经调过两次（复盘 + 日记），半夜再调一次只为做梦，
是拿最贵的资源做一个没人要求它更聪明的东西。梦的价值在**它出现了**。

**语言漂移**（`say.recent_tics`）

从她自己最近 80 条消息里统计 2 字词，至少出现在 3 条不同消息里才算"老爱说"。
挂进提示词：`你最近老爱说「确实」（3 条消息里都带着它）。可以让它留着`。

跨词边界是 2-gram 的固有问题（"这个东西就是这样"会切出「西就」「个东」），
加了一张虚字表挡：真词里几乎不会同时出现"就/是/的/了/个"这种字。

**隐私**（`narrative` 允许 `kind=unsaid`）

以前 `bond.KIND_UNSAID` 存在但**没有任何生产者**——又一个"字段有、没人写"。
现在复盘可以写：`{"kind":"unsaid","what":"想说但咽回去的那句"}`。
它挂在 `### 当时没说出口的` 段里，**只回到她自己眼里**，用户永远不知道。
判据写死：材料里要能看到停顿/改口/明明有话却只回了个短句，没有痕迹不许写——
编出来的"欲言又止"比直说还假。

**结束对话**（`policy.is_farewell` + `world._stopped_by_farewell`）

`-` 只表示"这一轮不接"，下一轮对方再来她照样说话。
而"我先去忙了"是**结束这段对话**——说完了再主动找他，就是打自己的脸。
检测到收尾语就不进入主动开口。

用"谁最后说话"而不是时间窗口：`history` 没有时间戳，硬记窗口要多一处会漂的状态；
而"她说了去忙、之后没人再说"这件事本身已经是状态——对方一开口，条件自动不成立。

**关系会消失**（`neighbors.GONE_AFTER_DAYS = 14`）

十几天没见过的熟人，说法就变成"换了个人，说是他回老家了""位子空着，
东西都收走了"。不带戏剧性——生活里的"不见了"一般没有下文，就是没了。

只涨不跌的不是关系，是账本。一个永远在场的邻居不是人，是背景板。

## 六、全量自检（2026-11-10 23:20）

### 6.1 日记回流会互相取代（真 bug，已修）

写两天日记，`facts` 里只剩一条 active —— 第二天把第一天当成"纠正"覆盖了。
根因：`_find_same` 按 `(owner, anchor, predicate)` 判"同一件事"，
而 `predicate="那天"` 固定、`anchor` 留空，于是每天的日记都是同一条事实。
修法：`anchor` 用日期（`MM-DD`）。实测三天三条都留着。

### 6.2 日记会 постепенно 挤掉别的（设计缺口，已修）

修好 6.1 之后，日记每天涨一条 —— 一年 365 条。而 `facts_for_prompt` 的
候选池只有 24~48 个位置，会被"那天"占满，把"关于他的事"挤出去。

这不是理论风险：用满一年必然发生。
加 `PER_PREDICATE_MAX = 3`：同一个谓词在注入段里最多 3 条。
实测 30 条日记 + 3 条关于他的事 → 别的事 3 条全在，日记只留最新 3 条。

### 6.3 `_remember_diary` 没检查 db 为空（已修）

CLI 入口下 `db` 可能是空串，`M.remember("")` 会抛异常，靠外层 try 兜住 ——
但那是拿异常当流程控制，日志里会一直刷。加了一行 `if not db: return`。

### 6.4 「晚安」不在收尾词表里（已修）

最常见的收尾语反而漏了。加进 `FAREWELL_MARKS`。
`is_farewell` 已经排除问句（"你睡了？"是关心不是告别）。

### 6.5 `MAX_CATCH_STEPS = 128` 只够 10 天（已修）

超过之后走"剩下的按一段算完"的兜底：30 天没开软件 ⇒ 她"醒着"
连续过完剩下的 20 天，energy 扣到地板 6，而真实情况是她睡了很多觉。

改成 512（覆盖 42 天）。实测关 30 天：**0.01 秒补出 291 个事件**，
今天 07:44 醒、energy 82、债 0 —— 正常。

### 6.6 界面刷新会替她掷骰子（已修）

`get_today` 里调 `catch_up(st, now)` 只为把精力补到此刻。
但 `catch_up` 会经过 `_wake`，那里会 `roll_body` / `roll_dream` ——
UI 每 5 秒刷新一次，醒来时刻附近就会反复重掷，`body_since` 一直变。

加 `catch_up(..., roll=False)`，`get_today` 传 False：
**界面只补算时间和精力，掷骰子是引擎的事。**

### 6.7 `history.load` 读整个文件（性能，已修）

```python
with open(path) as f:
    lines = f.readlines()      # ← 一年后是几 MB
```

而 `_tics_block`（新加的）**每轮都调一次**。改成从尾部按块往回读
（`_tail_lines`），读到够 n 行就停。实测 500 行文件读 5 条正常。

### 6.8 仍然"不对"但**故意的**三处

1. **`_peer_spoke` 会把"对方回应我第 1 条"也当成打断** —— 但"对方插话了
   就停"本身是对的，宁可少说一条。
2. **`_worth_showing` 对"同义改写"仍可能误判** —— 现在加了三条硬规则

3. **`catch_up` 的段数上限仍是硬的**（512 段 ≈ 42 天）—— 超过就走

## 七、独立审查（两路）+ 修复记录

2026-11-10 23:30，两路只读审查并行跑（一路专挑时间推进的边界，一路专挑
数据一致性与接线）。查出 12 处，全部先验证再修。

### 7.1 【最重】`list_facts(owner=A, tier=owner)` 其实返回**全库**

我以为上一轮"传了 owner"就修好了 —— **没有**。

`scope_filter` 在 `strict_owner=False` 下产出
`(owner IN (A) OR visibility IN (...))`，而 `visible_visibilities(TIER_OWNER)`
是**全部三种**，于是 OR 那一半恒真，owner 条件等于没写。

实测：用 A 的身份查，B 的私密照样返回。而 `facts_for_prompt` 早就补了一刀
（`if i["owner"] in mine`），world 的两处没有。

后果：别人的私密进日记正文、进复盘 `changed_view`（写进 `soul.selfNotes`
长期留存）、进日程 prompt —— 这是唯一一条"写出去就收不回来"的。
修：两处都自己再收一刀（`owner in {自己} | owner_persons`）。

### 7.2 【最重】`expire_plan` / `plan_for_prompt` 没有 plan_day 守卫

`current_plan_item` 有，这两个没有。后果是跨午夜那段窗口精神分裂：
doing 说"没在做计划里的事"，提示词却把**昨天的三条**渲染成
「## 你今天打算做的」。而且 `catch_up` 内部每个边界都用**历史时刻**调
`expire_plan`，一次长假补算会把陈旧 plan 按十几天前的时刻全标成"过去了"，
还会落盘。

实测（修前）：00:30 时 23:30–23:50 的条目 0 条被结算，要挂到次日 23:51
才一次性把三条全标掉。
修：两个函数都加「只认当天 plan」的守卫。

### 7.3 `current_plan_item` 不看 `done`

界面上点一次完成，下一次 5 秒 tick 又把这条写进 `state.doing` ——
她会说"我在去超市"而这件事早就标成做完了。区间命中和"提前 30 分钟"
两条规则都补了 `done` 判断。

（顺带：注释写 90 分钟、代码是 30，代码是对的，注释改回来了。）

### 7.4 `catch_up` 的段数兜底只算精力、不做边界转移

512 段只够 42 天，超过之后以前只跑 `_advance_flat` —— 于是 `day` 停在
十几天前、`energy` 扣到地板 6，而 `asleep`/`wake_at`/`just_woke_at`
还是老的，四个字段互相打架，**而且 `last_tick` 已推进 → 会落盘**。

实测关 30 天（修前，128 段）：`asleep=True`、`energy=100`、
`wake_at` 是 19 天前，`render` 输出「我已经睡了（22:50 睡的）」
——一个 19 天前的时间被当成今晚的睡醒时间。

修：兜底改成"按当前时刻重新对齐"（和原来那个 26 小时特判等价）。

### 7.5 repair 的哨兵用错了字段

`if t > deadline and state.wake_at > deadline` —— 拿 `wake_at` 当
"有没有这一觉"的哨兵，恰恰在 `wake_at=0`（旧数据）时把补睡关掉，
而 `wake_at=0` 还会让 `_wake` 去算 1970 年，Windows 上 `timestamp()` 直接抛。

修：哨兵改成 `deadline > 0 and t > deadline`，醒来时刻用 `_fall_asleep`
刚重算出来的那个。并且**不再把 t 回拨到 deadline** —— 回拨会让"已经按
清醒扣过费的窗口"再加一遍睡眠增益（实测 energy +23）。

### 7.6 陪聊延长被三重惩罚

`overtime` 的基准是 `bedtime` 而不是"允许她熬到的时刻"，于是她**被允许**
陪聊的 96 分钟照样按熬夜扣一次；同一段又被 `_fall_asleep` 计进睡眠债，
次日再扣起床精力和晚醒。

修：`_advance_flat` 的 overtime 用允许时刻（延长不算熬夜）；
`_fall_asleep` 的债仍按 `bedtime`（延长多少就真的少睡多少）——
两者**故意不同**，混用就是三重惩罚。

### 7.7 `set_plan` 的 `dur` 无 try

`int("45分钟")` 抛 ValueError，而调用方把异常当成"日程生成失败"——
**整天日程全丢**，不是丢这一条。加 `_clamp_int`（0–240）。
同时给 `at` 加范围校验：`"99:99"` 以前能落库，永不命中、永不 elapsed，
是一条永久占位的僵尸。

### 7.8 `_fact_score` 与 SQL 的 `confidence=0` 分歧

Python 写 `float(x or 0.5)`，`0.0 or 0.5` = **0.5**；SQL 的 `COALESCE`
因为字段 NOT NULL 而用真值 `0.0`。实测同一条事实，Python 排最前、SQL 排最后。
改成 `0.5 if x is None else float(x)`。

### 7.9 `use_count` 加成没有上限

注释写着"但上限"，代码没有。被注入过的每轮 +1，几十轮后排序完全由它决定，
时间衰减再也压不下去 —— "三年前的进不来"换个形式回来。
加 `USE_COUNT_CAP = 20`（0.6 上限），SQL 与 Python 同步。

### 7.10 `_worth_showing` 的判据方向反了

字符集 Jaccard 丢掉顺序和重复，精确地吞掉"高重合但语义全变"那一类 ——
而那一类最该出现在时间线里：

```
喜欢他 → 不喜欢他          被吞（子串）
620 → 602                  被吞（字符集相同）
猫咬狗 → 狗咬猫              被吞（字符集相同）
```

修：先判三种"一定值得看"（数字变了 / 否定翻转 / 同字换序），再看措辞重合。

### 7.11 `neighbors` 同一天重复计数

`note_seen` 无条件 `count += 1`，而档位是 `count // 3` —— 同一天
`attach` 被调两次（重启后重排日程就会），"卖鱼的"会从"摊子空着"
变成"多塞了一条小鲫鱼"，日程、日记、复盘三处说法互相打架。
修：同一天只记一次。

顺带：`guard` 的匹配词里有"取快递"且排在 `courier` 前面，
于是"取快递"永远只碰见保安，送快递的小哥几乎不出场 —— 去掉那个词。

### 7.12 `history.load` 读整个文件

`readlines()` + 切最后 N 行，而 `_tics_block` **每轮都调一次**。
文件一天几十上百行，一年几 MB。改成从尾部按块往回读（`_tail_lines`）。

（`get_today` 里 `jw` 在 `catch_up` 之前读，导致"刚醒"那一刻界面说她
没醒过 —— 也已修，移到补算之后重读。）

## 八、把"半成品"补满：心情底子 / 起床流程 / 自己的动机

用户说"按顺序开始都做"。三件都不是新功能，是把已经做了一半的东西补到能自洽。

### 8.1 心情有了**底子**（`mood_judge.baseline_of`）

以前心情永远往 `moodBase = 70` 衰减 —— 于是睡差了、身上难受、连着阴三天，
**底子都是 70**。首页那个"心情 70 · 心情不错"不是实时心情，是衰减后的余数。

现在底子由四样推出来：

```
睡眠债  每小时 -3，封顶 -12（欠满 4 小时就是 -12）
精力    <25 → -8 / <40 → -5 / <55 → -2 / >85 → +3
身体    有一点不舒服 → -4
天气    雨雪阴雾霾 → -3 / 晴 → +2
```

实测四档：**75 / 67 / 55 / 43**。下界 25、上界 92 —— 再差也不该让她
永远在低情绪（那是演），再好也要留余地给事件（不然一件好事顶满，之后全是回落）。

`decay_only(baseline=...)` 用它当衰减目标；`world._mood_baseline()` 负责组装
（睡眠债 + 精力 + `body_now` + 天气），任何一块取不到就给中性值 ——
底子算错比没有底子更糟。

### 8.2 起床变成**有顺序的三步**（`life.WAKE_STEPS`）

以前那 55 分钟只是"被占掉"（`plan.WAKE_BLOCK_MINUTES`），所以她的早上从
"在煮点东西"直接跳到"去趟超市"，中间没有"收拾一下准备出门"。

```
0–15 分钟   刚起来，还在洗漱
15–35 分钟  在弄点吃的
35–55 分钟  收拾一下，准备出门
```

而且它**优先于日程**：她 08:58 才醒，09:00 那条"去趟超市"不可能正在做。
`plan.WAKE_BLOCK_MINUTES` 同步改成 55 —— 两个数必须 ≥ 关系，否则会排出
"她还在洗漱、日程说她在超市"。

### 8.3 她有了**只跟自己有关**的动机（`plan.self_material`）

以前日程的素材只有 `yesterday / fact / self`，而 fact 全部来自对话 ——
**她做的每件事最终都能追溯到你**。一个人如果所有动机都要经过另一个人，
那她不是独立的，是被驱动的。

现在 `build_request` 多一段「## 你自己会想到的」，材料全部来自**她的处境**：

```
- 身上：眼睛有点干（不用硬撑，该歇就歇）
- 最近碰见：卖鱼的：摊子空着，蓝布盖着
- 天气：12°C，阴，11~16°C
- 这段时间一直在：在收拾屋子
```

提示词第 8 条允许她据此排一条 `from="self"` 的事，并且明确：
**"它不需要和他有关 —— 身上难受就去买点药，天晴了就想晒被子。"**

"一直在做的事"用同一条 doing 出现 ≥2 次来判 —— 那是她手上有件没弄完的活，
不是随手做的。

### 第 4 步落地后的实际形状

模型只判断「大致什么时段做什么」（它擅长的粗判断），
落点、时长、间隙全部由 `plan.layout()` 算（它不擅长的算术）：

```
醒 07:53，睡 23:20
  09:00-09:50 (50分)  去趟超市        [上午]
  13:00-13:40 (40分)  把汤热一热      [中午]
  13:50-14:35 (45分)  翻几页小说      [下午]
  17:00-17:30 (30分)  做顿饭          [傍晚]
```

守的几条不变式（都进了测试）：

- **区间不重叠**，两条之间留 10 分钟走动 —— 她不可能同时在两个地方
- **避开 11:40–12:30 / 17:40–18:40 / 21:40 之后**，谁都不许排进去
- **从醒来算起**，不从 08:00 算起 —— 她 11:00 才醒就不会有 09:00 的事
- **偏好时段装不下就往后放**，不塞回更早的时段（否则会 10:00 吃午饭）
- **因果补前置**：排了「做饭」却没有「买菜」，自动在上午补一条"下楼买点菜"
- **区间过完自动结束**（`expire_plan`），她第一次真的会"做完"一件事

### 第 5 步落地后的实际形状：有了「别人」

新建 `bigfish/neighbors.py`：**五个固定熟人**，永远不会有第六个。

```
卖鱼的（菜市场）：话极少，称完总往袋子里多塞一条小的
楼下喂猫的老太太（单元门口）：认得每一只猫，从来不记得人的名字
小区保安（门口）：值夜班的时候一直看手机
面馆老板（楼下）：记得她不吃香菜
送快递的小哥（快递柜）：总是跑着来，说话的时候还在喘
```

每天生成日程后，`neighbors.attach()` 按活动地点匹配，50% 概率挂一个「碰见」，
一天最多两次。十天实测：

```
13:00-13:30  下楼走一圈  ← 碰见楼下喂猫的老太太：今天带了新的猫粮，袋子是拆过的
```

三天里的三种说法：

```
"今天在，还是不爱说话" / "摊子空着，蓝布盖着" / "多塞了一条小鲫鱼，也没说要钱"
```

三条刻意守住的克制：

1. **遭遇没有剧情。** 不写"卖鱼的说他女儿考上大学了"——那是有用的信息，
   会被她拿去跟你聊；一旦它有用，它就变成了道具。生活的大部分没有信息量。
2. **人固定，状态会变。** 变的不是人，是日子。
3. **只有一个去处。** 挂在日程条目上的 `meet` 字段，跟着 `plan_for_prompt`
   和日记素材走。没有独立注入面，不会挤掉记忆和对话。

同时破掉两条禁令：

- `narrative.py`「不要写对第三方的评价」→「可以写那几个熟人今天怎么样，
  **不许替他们下判断**，也不许新增材料里没有的人」
- `journal.py`「绝对不许编对话」→「不许编**对方**的对话；材料里给的人可以写
  你看的那一眼，不替他们编话、不替他们解释」

### 顺手修掉的三处（都是审查中挖出来的确定性缺陷）

1. **复盘/日记的事实在全库混排**：`world.py` 两处 `list_facts` 没传 `owner`+`tier`。
   `memory.py` 明写「管理视角只能给 UI 用，任何注入提示词的路径必须传 owner」——
   不传就是别人的私事会被写进全局 `soul.json`。现在两处都传了。
2. **关系阶段「能收不能生成」**：`STAGE_WORDS` 有 10 个词，给模型的只有 6 个，
   「很熟」「亲近」「有点熟了」「冷淡」模型想写也写不出来，只能退回近义词。
3. **`set_plan` 丢掉区间**：排好的 `start`/`end`/`dur` 在落库时被字段清洗抹平，
   `_plan_end_minutes` 只能退回 `at+30`——一条一小时的"去趟超市"半小时就过去了。

第 3 步之前的每一步都**不动提示词的语义**，只改数据流和算法，风险可控。
第 4 步开始会明显改变她的观感，每步都要跑一晚上再往下。
