# 检查更新

> 设置 → 关于 → 检查。

## 以前为什么不能用

点「检查」只得到一句：

```
未配置更新仓库（config.json 的 update.repo）
```

两个问题叠在一起：

1. **仓库默认是空串。** 「能不能检查更新」不该取决于用户有没有手改 JSON。
2. **当前版本读的是 `config.json` 的 `update.current`**，而那份配置里写死了
   `"0.1.0"`。程序走到 0.4.1 了它还是 0.1.0，于是拿 0.1.0 去比 Release 的
   `v0.4.0` —— 显示「发现新版」。用户点了更新，装回来还是同一个版本。

## 现在

**零配置可用。** `update.repo` 留空就用内置的：

```python
DEFAULT_REPO = "q825818504/bigfish-wechat"
```

fork 的人填自己的（填完整 URL 也行，`normalize_repo` 会收拾）：

```
https://github.com/a/b          → a/b
https://github.com/a/b.git      → a/b
github.com/a/b/releases         → a/b
git@github.com:a/b.git          → a/b
```

**当前版本只认 `bigfish/__init__.py` 的 `__version__`。** 配置里不再有
`update.current` 这个字段 —— 版本号散在多个地方必然对不上，这个项目已经
被同一类问题坑过三次（`__version__` 曾散在三处、`CONFIG_PATH` 定义了两遍、
`build_portable.py` 写死 0.3.1）。

## 界面显示什么

```
关于                                    v0.4.1
──────────────────────────────────────────────
检查更新                                  [检查]
从 GitHub（q825818504/bigfish-wechat）读取最新版本。

新版本 0.5.0（当前 0.4.1，2026-11-05）  [下载并安装]
模型接入：19 家预设，选一家填 Key 就能用。
```

**当前版本和最新版本必须同时可读。** 只报「发现新版」而不说自己在哪一版，
用户没法判断该不该装。

顶栏那个下载图标是快捷入口 —— 点了跳到这一行，**不直接下载**。
图标一点就开始下两百兆太容易误触。

## 流程

```
点「检查」
  → GET api.github.com/repos/{repo}/releases/latest
  → 比 tag_name 和 __version__
  → 有新版：亮出「下载并安装」那一行

点「下载并安装」
  → 从 Release 附件里挑 .exe（没有就 .zip）
  → 下载到 .tmp/update/，校验 sha256（Release 里有 digest 时）
  → schedule_replace()：写一个替换脚本
  → 用户关掉程序，脚本把 exe 换掉并重启
```

开发态（`python -m bigfish.desktop`）不能替换 —— 会覆盖 `python.exe`，
代码里显式挡住了，只提示不执行。

## 限流

GitHub 未认证 API 是 **60 次/小时**。所以：

- 用 `ETag` 缓存（`If-None-Match`）。304 时服务器不返回正文，不计数
- 启动时静默检查一次（2.5 秒后），失败不打扰用户
- 手动点「检查」走缓存，连点几下不会打爆

304 的代价是拿不到最新版本号，只能显示「已是最新（0.4.1，本轮走缓存）」。
这个提示在 `cached: true` 时会出现，用户能看出差别。
