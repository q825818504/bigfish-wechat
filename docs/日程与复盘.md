# 日程、复盘与感知

> v0.10.0 起生效。这一层回答的是：**她怎么过日子，以及她会不会变。**

---

## 一、日程（872）

### 她的一天从哪来

每天**醒来后**（不是 0 点）生成一次，排 2~3 件事：

```
09:30 去趟超市          ← 来自昨天没做完的事
14:00 把上次的书看完     ← 来自昨天提到的事
20:00 下楼散步          ← 她自己排的
```

### 一条硬约束：至少一条接昨天

只让模型"随便排三件事"，它会排出三件互不相干的日常，每天都是新的 ——
那还是采样，只是换成了模型采样。

所以 `from` 字段里必须有至少一个 `yesterday`。模型不听话时，
`ensure_yesterday()` 从昨天素材里取第一条没做完的，塞到最晚时段。
补的内容来自素材，不是编的。

### 只排什么事

**可以**：买菜、收拾屋子、洗衣服、看书、做饭、散步、取快递、发呆、晒太阳。

**不排**：会议、面试、就医、考试、长途出行、需要安静/专注的事。

理由和「手头在做什么」一样：写了"10:00 开会"，她 10 点还在回你消息，
就是在打自己的脸。

### 它怎么影响她

- 「手头在做什么」优先从日程取当前时段那条；
- 没生成 / 生成失败 → 退回原来的静态池（在看书、在收拾屋子）；
- 日程会进提示词：「## 你今天打算做的」，带「（做完了）」标记。

### 怎么看

日志：`[日程] 今天：09:30 去趟超市 / 14:00 把书看完 / 20:00 散步`

关掉「日程」插件：她不再说，但日程照常影响她手头在做什么。

## 二、睡前复盘（写灵魂 + 写关系）

### 什么时候跑

**入睡前 30 分钟**，一天一次。

为什么不放 0 点：23:40 她还在跟你聊，0 点突然"复盘今天"——
今天还没过完。

### 一次调用，写两个地方

| 产出 | 写到哪 | 长什么样 |
|---|---|---|
| `changed_view` | `soul.json` 的 `selfNotes` | `（11-08）关于他：以前不在乎我，现在只是太累了。` |
| `relation_events` | `memory.sqlite3` 的 `bond_events` | `11-08 他第一次说累（靠近）` |
| `stage`（可选） | `bonds` 表 `kind='stage'` | `有点依赖` |

### 灵魂的三条保护

1. **只追加**，不覆盖你手写的条目；
2. 自动条目**上限 12 条**，超了只删自己长出来的
   （靠 `（MM-DD）` 前缀识别，手写的没有前缀，永远不删）；
3. `history` 里留 `{from, to, why}`，能追到是哪天因为什么改的。

`whoIAm` / `values` / `traits` **一个字不动**。她能变的只有
「我自己知道的事」这一段。

### 最难的约束：允许她今天没什么可写

`changed_view` / `relation_events` 都可以是空数组。
素材里没有情绪波动、没有冲突、没有新约定 → 全空。

模型最擅长"把空的说成有的"。只写"输出 changed_view"，它每天都会给两条 ——
一周后 `selfNotes` 全是互相矛盾的"我现在觉得"。

`changed_view` 也不是"今天发生了什么"：

```
❌ 今天他加班到十点。          ← 这是事件
✅ 我以前觉得他不在乎我，现在发现他只是累。  ← 这是看法
```

### 关系阶段

白名单，不是自由文本：

```
刚认识 / 有点熟了 / 熟了 / 很熟 / 有点依赖 / 亲近
/ 闹过别扭 / 和好了 / 有点疏远 / 冷淡
```

阶段不是"好感度"，是一句描述。它只影响称呼和分寸，不影响任何权限。

### 关系事件

五种：`warm` 靠近 / `conflict` 摩擦 / `promise` 约定 / `first` 第一次 /
`repair` 和好。

按 `(kind, what)` 去重，只追加、不覆盖 —— 关系是时间线，不是一张当前状态卡。

和「称呼 / 没说出口的话」的区别：**事件不需要原话子串证据**。
"第一次一起看电影"本来就没有一句原话，硬套证据约束只会逼模型编一句来凑。

### 怎么看

- 灵魂：面板「灵魂」页 →「我自己知道的事」，新条目带日期前缀，可以直接删；
- 关系：面板「印象」页 → 现在会多一段「你们之间发生过的」和「我们现在」；
- 日志：`[复盘] 自述 +1，事件 +1，阶段→有点依赖｜今天他说了加班。`

## 三、睡前道别

入睡前 20 分钟，如果你们最近 40 分钟还在聊，她会说一句「我先睡啦」再睡。

| 条件 | 说明 |
|---|---|
| 她醒着，且在 `bedtime - 20 分钟` 内 | 不是固定钟点，跟着她每天浮动的入睡点走 |
| 最近 40 分钟有过互动 | 对方说话，或她自己回过话，都算 |
| 今天没说过 | 一天一次 |

**不占主动额度。** 把「一天最多几条」设成 0 的人也该有道别 ——
它不是"她还想找你说话"，是"到点了，说一声"。

**不进「待回」。** 没人回"晚安"是预期之内的事；放进去会让她第二天
追问"你怎么没回我晚安"。

**她也可以不说。** 模型输出 `-` 就直接去睡。有些人困了就是这样。

日志：`[道别] 她困了：我先睡啦` / `[道别] 她没说什么，直接去睡了`

## 四、感知

### 三样东西

| 来源 | 怎么来 | 什么时候出现 |
|---|---|---|
| 天气 | Open-Meteo（免 key），城市在「生活」插件里填 | 缓存 30 分钟；超过一天不认 |
| 节日 | 公历固定节日（元旦/情人节/劳动/儿童/国庆/平安夜/圣诞） | 当天 |
| 近期事件 | 从「你认定的事」里抽 `X月X日`，只抽 0~3 天内 | 抽到才出现 |

农历节日**不做**：准确的农历要天文算法，把中秋算错一天，
她会提前一天说"中秋快乐"，比不说糟得多。

### 两条硬约束

1. **拼 prompt 时绝不联网。** `_compose` 跑在引擎线程，一次 4 秒超时
   就是"她突然不说话了"。联网在 `world.tick` 的后台线程，30 分钟一次。
2. **只读缓存。** 缓存过期也照用旧值 —— 昨天的天气比"没有天气"好，
   比卡住更好。但超过 24 小时的天气不认（12°C 说出来是错的）。

### 它会怎么出现

> ## 你注意到的
>
> - 杭州现在 12°C，多云。
> - 今天是圣诞节。
> - 你记着 11月10日：他说要去面试。

提示词里明确要求："没被问到就顺口提一句，不要当成天气预报来播报。"

## 五、关掉会怎样

| 关掉 | 她还会 | 她不会 |
|---|---|---|
| 日程 872 | 按日程决定手头做什么 | 说"我今天打算……" |
| 余韵 930 | 记录、衰减、影响预算 | 说出来、带着它说话 |
| 主动（原） | 回你 | 先开口、追问、check_in |

日程生成和睡前复盘**不受插件开关影响**（它们是状态，不是嘴）——
只有联网和模型调用失败时才会退回去。

| 每晚睡前 | 1 次（复盘，写灵魂 + 关系） |
