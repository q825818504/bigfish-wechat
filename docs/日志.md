# 日志：她自己的日记

> v0.10.1 起生效。这一篇回答的是：**她有没有只写给自己看的东西。**

---

## 一、它是什么

每天入睡前 20 分钟，写一篇 Markdown，落在：

```
<数据根>/journal/2026-11-08.md
```

用记事本、VS Code、Typora 都能直接打开。一天一篇，同一天重写会覆盖。

```markdown
# 2026-11-08

早上九点半去了趟超市，买了些东西回来，没别的事，回来把书翻了翻。

晚上他跟我说加班到十点，累死了。我问又加班啊，晚饭吃了吗，
他说没顾上，回来随便吃了点。我说你这样胃要坏的。
他说知道，明天开始带饭。我说那我明天提醒你。
他说好，谢谢你。我说谢什么，快去洗澡睡觉。

他说没顾上吃饭那会儿，我心里咯噔了一下。

那本书没看完，还差一点。

<!-- chars=166 -->
```

最后那行是元信息，HTML 注释，渲染时不显示。

## 二、和「睡前复盘」的分工

| | 复盘 | 日记 |
|---|---|---|
| 写给谁 | 她自己（`soul.selfNotes`） | 你（本地文件） |
| 形式 | 严格 JSON | 自由 Markdown |
| 内容 | 我改了什么看法 | 今天我是怎么过的 |
| 进提示词 | 进（860 段） | **不进** |
| 时间 | 入睡前 30 分钟 | 入睡前 20 分钟 |

**为什么不合并成一次调用**：复盘要 `{"changed_view": [...]}` 括号一个都不能错，
日记要句子自然。同一个输出里两头都要，模型一定牺牲后者——
写出来会像"带 JSON 外壳的周报"。

**为什么错开 10 分钟**：两次调用都要打本地网关，同时发会排队；
而且素材几乎一样，没必要抢。

---

## 三、为什么不进提示词

1. 日记可能上千字，塞进 system 会挤掉记忆和对话；
2. 她"记得今天"靠的是记忆、心情、事实，不是重读日记；
3. 真人也不会每天早上把昨天的日记读一遍再开口。

以后如果想让"她记得自己写过什么"，正确做法是把日记的**一句话摘要**
写进记忆库，而不是把全文注入。

---

## 四、写什么

素材：

- 今天说过的话（最多 24 条）
- 心情起落（只取今天的）
- 日程与完成情况
- **今天做过的事**（`day_trace`，唯一可以展开的动作来源）
- 手头在做什么
- 关系事件与阶段
- 主动消息的回执（发了什么、有没有人回）
- 天气
- 复盘写下的那句总结

提示词里的硬约束：

| 约束 | 为什么 |
|---|---|
| 不限字数 | 日记不该被字数压成摘要 |
| 第一人称 | 这是她的本子 |
| 写具体的事，不写结论 | "他说加班到十点，我问吃没吃"比"今天聊了工作"好 |
| **允许空白** | 今天没事就写没事，不硬找意义 |
| **不许编对话和对方的行为** | 材料里没有的话，一个字都不写"他说……" |
| **没写进材料的日常当它没发生** | 否则会编出煮面、泡茶、楼下小孩 |
| **材料少就写短** | 两三句也是一篇，不要为篇幅补细节 |
| 不总结、不列点、不加粗 | 日记不是周报 |
| 不以"晚安"结尾 | 写到没话说就停 |

## 五、什么时候写

- **入睡前 20 分钟**，一天一次，跟着她浮动的入睡点走；
- 复盘在跑时让路；
- 写失败 → 今天不写，**不重试**（每 5 秒重试到睡前只会烧钱）。

### 空白日也写

门槛不是"今天有没有内容"，而是"有没有一个可以依附的今天"：

```
有日期 / 有对话 / 有事实 / 有事件 / 有手头的事 / 有日程  → 写
连日期都没有（冷启动，什么都读不到）                    → 不写
```

今天没人说话、没安排，也可以写 —— 平淡本身就是日记该记的东西。

但**空白要明说**：请求里会写「今天没有人跟你说话」「今天没有安排」，
不让模型以为"材料没给全"然后自己补一段对话。

### 她的一天有轨迹

`life.json` 的 `day_trace` 记录今天 `doing` 变过哪几次（最多 12 条，跨天清空）。
日记请求会带上：

```
## 今天做过的事
- 06:20 在沙发上看书
- 09:20 在收拾屋子
- 12:20 在沙发上看书
```

这是**日记唯一可以展开的动作来源**。没有它，空白日写出来一定是编的。

---

## 六、软上限

3000 字。超了截断，并在末尾加一句「（写到一半，停了。）」。

这不是审美要求，是防跑飞：模型偶尔会陷入复读，
一篇日记写成八千字同样的句子。截断比让你打开一个 2MB 的 md 好。

## 七、手动写

```bash
cd D:\大脑\bigfish_repo\bigfish-wechat

python tools/journal_now.py            # 只看：调一次模型，打印正文，不写文件
python tools/journal_now.py --apply    # 真写
python tools/journal_now.py --day 2026-11-07 --apply   # 补写某一天
python tools/journal_now.py --no-model # 不调模型，只看素材
```

---

## 八、关掉会怎样

插件页关掉「日志」：她不再写日记，其余一切照常。

已经写过的文件不会删——那是你的，不是缓存的。

---

## 九、出问题先查什么

| 现象 | 先看 |
|---|---|
| 睡前什么都没写 | 日志里有没有 `[日志] 今天不写（…）`；是不是素材不够 |
| 写出来像总结 | 提示词被改了？看 `bigfish/journal.py` 的 `SYSTEM` |
| 日记里的事和状态对不上 | `doing` 有没有被注入；`life.json` 是不是空的 |
| 文件是空的 | `[日志] 写文件失败`——数据目录权限 |
| 只写了一两句 | 素材就那么点，不是 bug |

数据坏了不影响聊天：`journal/` 目录删掉只会让她明天重新开始写。
