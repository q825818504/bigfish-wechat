# 模型接入

> 设置 → 模型：选一家 → 粘 Key → **点「获取模型」拉真实列表** → 选一个 → 测试连接。

## 流程

```
选一家         填 API Key        接口地址自动填        点「获取模型」
   ↓               ↓                  ↓                    ↓
DeepSeek   →   sk-...        →   https://api.  →   GET /v1/models
                                  deepseek.com/v1   → 真实列表
                                                          ↓
                                                    选一个 → 测试连接
```

**模型列表是拉出来的，不是猜的。** 第一版这里写的是硬编码的模型建议
（`datalist`），那是偷工减料：模型一更新就过期，而且「你这把 Key 能用哪些」
本来就不是常量 —— 免费额度、区域限制、企业版都会不一样。

magpie 的 README 写的也是这个意思：*"Model lists come from the vendor"*。
模型名和推理档位这类元数据可以来自 models.dev（公共知识），但**具体哪几个
你能用**只有对方知道。

拉不到怎么办：直接在下面的输入框手填。这条后路必须留着 ——
有些中转站没实现 `/models`。

## 为什么改

以前模型页只有三个裸字段：接口地址 / 模型 ID / API Key。等于要求用户自己知道：

- DeepSeek 的地址是 `https://api.deepseek.com/v1/chat/completions`
- 模型 ID 叫 `deepseek-v4-flash`
- **Claude 根本不走 OpenAI 格式**，字段名全不一样

默认值又指向 `127.0.0.1:3425`（Magpie 本地网关）。结果就是：除了本机装了
Magpie 的那一个人，**别人拿到这个程序配不出模型**。换用户、换电脑直接废。

## 三条路

| 方式 | 选什么 | 要填 |
|---|---|---|
| **主流模型** | 预设（DeepSeek / Kimi / 智谱 / 通义 / 豆包 / MiniMax / OpenAI / Claude / Gemini / OpenRouter …） | 只填 Key |
| **自定义** | `自定义（任意 OpenAI / Anthropic 兼容）` | 接口地址 + 模型 ID + Key |
| **第三方网关** | `Magpie 网关`（本机），或者自定义里填别人的 Magpie 地址 | 本机不用填 |

预设给的是**填好的默认值**，不是白名单。地址、协议、模型 ID 三项都可以改 ——
中转站、公司内网、自建服务全走「自定义」。

## 配置长什么样

保存后写在 `config.json` 的 `llm` 段：

```json
{
  "llm": {
    "channel": "deepseek",
    "base_url": "",
    "model": "deepseek-v4-flash",
    "api_key": "sk-...",
    "protocol": "openai",
    "temperature": 1.0,
    "max_tokens": 2600,
    "timeout": 90
  }
}
```

`base_url` 留空 = 用预设的。`protocol` 留空 = 用预设的。

## 获取模型列表的实现

三种协议都有 `/models`，形状略有不同：

| 协议 | 地址 | 响应 |
|---|---|---|
| OpenAI 兼容 | `GET {base}/models` | `{"data":[{"id":"…"}]}` |
| Anthropic | `GET {base}/models` | 同上（形状一致） |
| Gemini | `GET {base}/models?key=…` | `{"models":[{"name":"models/…","supportedGenerationMethods":[…]}]}` |

Gemini 要多做两件事：去掉 `models/` 前缀，以及过滤掉
`supportedGenerationMethods` 里没有 `generateContent` 的条目
（embedding、aqa 这些在聊天里没用）。

中转站偶尔返回别的形状（`{"models":["a","b"]}`、裸数组），
`_parse_models()` 都兜住了。

**不强制要求 Key。** 有的家 `/models` 是公开的 —— OpenRouter 就是，
没 Key 也能看到全部 453 个模型。挡在前面的坏处是用户想「先看看这家有
什么模型」都不行；要认证的会返回 401，如实报出来就行。

## 三种协议的真实差异

这是整个功能最硬的骨头。各家不是"换个地址"那么简单。

| | OpenAI 兼容 | Anthropic | Gemini |
|---|---|---|---|
| 地址 | `POST {base}/chat/completions` | `POST {base}/messages` | `POST {base}/models/{id}:generateContent` |
| 认证 | `Authorization: Bearer` | `x-api-key` + `anthropic-version: 2023-06-01` | `?key=` 查询参数 |
| system | `messages[0].role = "system"` | **顶层字段 `system`** | `systemInstruction.parts[].text` |
| 正文位置 | `choices[0].message.content` | `content[]` 里 `type=="text"` 的块 | `candidates[0].content.parts[]` |
| 推理内容 | `message.reasoning_content` | `content[]` 里 `type=="thinking"` | `parts[]` 里 `thought: true` |
| token 参数 | `max_tokens` | `max_tokens` | `generationConfig.maxOutputTokens` |

三个最容易踩的：

1. **Anthropic 的 system 是顶层字段。** 塞进 `messages` 会被 400 拒掉
   （`unexpected role "system"`）。
2. **Gemini 的 key 不走请求头。** 放 `Authorization` 里会 400。
3. **Gemini 的模型名在 URL 里**，不在请求体里。

Kimi、智谱、豆包、通义、硅基流动、OpenRouter、xAI、Groq、Mistral、
Ollama、LM Studio 都是 OpenAI 兼容，归第一类。

## 地址不是"都一样"

几个写错就会 404 的：

| 家 | 地址 | 注意 |
|---|---|---|
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | 是 `/api/paas/v4`，**不是** `/v1` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 海外账号 `dashscope-intl` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | 模型 ID 带日期后缀 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | 模型名带组织前缀 `zai-org/GLM-5.2` |
| Kimi | `https://api.moonshot.cn/v1` | 海外是 `.ai` |
| MiniMax | `https://api.minimax.chat/v1` | 海外是 `api.minimax.io` |

这些地址都真发过请求验过（`tools/probe_providers.py`），15 家全部返回
401/400 —— 说明地址对，只是假 Key 被拒。

## 用户粘了完整地址怎么办

非常常见：直接把文档里的 `https://api.deepseek.com/v1/chat/completions`
粘进「接口地址」。

`providers.normalize_base()` 会剥掉后缀，只留前缀：

```
https://api.deepseek.com/v1/chat/completions  →  https://api.deepseek.com/v1
https://api.anthropic.com/v1/messages          →  https://api.anthropic.com/v1
.../v1beta/models/gemini-2.5-flash:generateContent → .../v1beta
```

不剥的话会拼成 `.../chat/completions/chat/completions`，用户看到的是一句
莫名其妙的 404 —— 这种 bug 最难查，因为他"明明填对了"。

## 出错怎么看

「测试连接」会真发一次最小请求（`max_tokens=24`），四种问题都在这一步暴露：
字段没填、Key 无效、地址不通、模型名不存在。

错误码翻成了人话：

| 码 | 提示 | 多半是 |
|---|---|---|
| 400 | 请求格式不对，检查模型 ID 和协议 | 模型名错，或协议选错 |
| 401 | Key 不对或没带上 | 复制不全、多了空格 |
| 402 | 余额不足 | — |
| 403 | Key 没这个模型的权限 | 或地区限制 |
| 404 | 地址或模型不存在（会带上当前地址） | 地址少了 `/v1` 之类 |
| 422 | 参数不被接受 | 协议选错了，Claude 不走 OpenAI 格式 |
| 429 | 请求太频繁或额度用完 | — |

网络层的 `SSL: UNEXPECTED_EOF_WHILE_READING` 这类也会翻成
「连不上：域名不通、被拦截，或者地址写错了」。

## 配置文件只有一个位置

```
<安装目录>/config.json      ← 就是这里
<安装目录>/data/            ← 记忆 / 情绪 / 插件
<安装目录>/_internal/...    ← 程序自己的东西，升级时整个换掉
```

**不在 `_internal` 里。** 那里是程序资源，每次打包都会被整个覆盖。

这个坑踩过两次，两次表现都是「保存成功，但界面刷新后又变回去」：

1. `desktop.py` 里 `CONFIG_PATH` 被定义了两次，第二次指向 `_internal`，
   静默覆盖了第一次那个正确值。
2. `deploy.py` 覆盖 `_internal` 时，先把它整个换掉、再想去读里面的配置 ——
   那时文件已经没了，"迁移"什么都没做，而且不报错。

规范在 `bigfish/paths.py` 的文档里写着：

```python
DATA_DIR    = os.path.join(app_root(), "data")
CONFIG_PATH = os.path.join(app_root(), "config.json")
```

`app_root()` 打包后 = exe 所在目录。所有路径判断都走它，不要自己拼 `__file__`
或者 `sys._MEIPASS`（那是资源根，不是用户目录）。

## 老配置自动迁移

老的顶层字段还在认：

```json
{ "endpoint": "http://127.0.0.1:3425/v1/chat/completions",
  "model": "workbuddy-ai/deepseek-v4.1-flash" }
```

读进来会映射成 `channel = magpie`（地址里含 `127.0.0.1:3425`）或
`channel = custom`（其它），地址剥成前缀。**升级不会弄丢现有配置。**

在界面上保存一次之后，顶层老字段会被清掉，只剩 `llm` 段 ——
留着两套会打架（改老字段不生效，跟 `CONFIG_PATH` 那个坑同一个形状）。

## 加一家新供应商

`bigfish/providers.py` 的 `PRESETS` 里加一条：

```python
Preset(
    id="newco",
    name="NewCo",
    base_url="https://api.newco.com/v1",
    models=("newco-large", "newco-mini"),
    key_hint="console.newco.com → API Keys",
    doc="https://console.newco.com",
),
```

OpenAI 兼容的话就这些。不是的话加 `protocol="anthropic"` 或 `"gemini"`，
再在 `replier.py` 里补一套请求体 / 解析函数（`_body_*` / `_parse_*`）。

跑一遍：

```bash
python tools/selftest_providers.py    # 83 个断言，不联网
python tools/probe_providers.py newco # 真发一次假 Key，看地址对不对
```
