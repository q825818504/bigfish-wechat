# 声音

> 她不只是回字、回图，还能**用她自己的声音**说话。
> 当前实现：Breeze Blue 云端声音模型（可克隆音色、原生支持情境指令）。
> 微信发送：音频文件已接；语音气泡是实验链路（VB-CABLE + UIA 录音）。

---

## 一、为什么不是「接一个 TTS 库」

普通 TTS 是「给字，出一段机器腔」。这里要的是**模型**：

- 音色是**她的身份**，定下来就不该每轮变；
- 同一句话，深夜、刚醒、拌嘴后、对方难受时，念法不一样；
- 这些差异不是靠调语速硬凑，而是靠模型原生的 `instructions`
  （情境、意图、情绪强度、节奏）和音频标签（`[叹气]`、`[停顿]`）。

所以架构和 `providers.py` 接模型一样：**选一家、填 Key、发一次真请求**，
而不是把某个 TTS 库写死在发送层里。

## 二、模块

| 文件 | 职责 | 关键设计 |
|---|---|---|
| `bigfish/voice.py` | 核心：配置、请求、缓存、体检、失败语义 | 只产出文件，不碰微信；不自动重试超时 |
| `bigfish/voice_audio.py` | 读 WAV、量指标、判合格、统一 24k | 纯标准库；不合格不算成功 |
| `bigfish/voice_director.py` | 她的状态 → 场景 → instructions/标签/参数 | 18 个场景 + 音色基线（薄荷） |
| `bigfish/voice_policy.py` | 这一轮要不要出声 | 模式/触发/概率/冷却；纯函数，可单测 |
| `bigfish/voice_audio_out.py` | 把 WAV 播到指定 Windows 播放设备 | 纯 ctypes/winmm，不依赖 sounddevice；选 CABLE Input |
| `bigfish/voice_bubble.py` | 微信语音气泡：按住录音键 + 播进虚拟声卡 | 参考 whale_girl；失败分级，按过键就绝不补文字 |
| `bigfish/plugins/voice.py` | 插件开关（hook+prompt） | 勾选后侧边栏才出现「声音」页 |
| `bigfish/voice_text.py` | 念之前的清洗与切段 | 保护 `[叹气]` 这类音频标签，别当表情删掉 |

数据流：

```
mood.json / life.json / afterglow.json / 对方这句话
        ↓  voice_director
{ text + [标签], instructions, speed=1.00, guidance, volume }
        ↓  voice.py
POST /v1/text-to-speech/{voice}?output_format=wav_24000&delivery=sync
        ↓
WAV → voice_audio 体检（时长/RMS/静音/削波/语速）→ 缓存 / 交给发送层
```

## 三、配置

写在 `config.json` 的 `voice` 段（和 `llm` 同一层）：

```json
{
  "voice": {
    "engine": "breezeblue",
    "base_url": "https://api.breeze.blue",
    "path": "/v1/text-to-speech/{voice}",
    "api_key": "brz_...",
    "model": "breeze-tts-2-multilingual",
    "voice": "YOUR_VOICE_ID",
    "language": "zh",
    "speed": 1.0,
    "guidance": 2.0,
    "volume": 1.0,
    "output_format": "wav_24000",
    "profile": "bright_young",
    "timeout": 90,
    "cache_mb": 200,
    "max_turn_chars": 400
  }
}
```

- **Key 不进仓库**。`config.json` 是用户目录里的文件；示例配置里是空串。
- 总开关在插件页勾选 **声音**；`voice.enabled` 只是兼容旧配置，不作为门。
  合成层不自己查插件开关 —— 调用方先问 `plugins.is_enabled("voice")`，
  避免「插件关了但代码还在合成」的两套开关。
- 音色固定 `YOUR_VOICE_ID`（薄荷）。换音色只改这一处，不要让模型每轮选。
- `speed` 固定 `1.00`：情绪只走 instructions 和停顿，不用 time-stretch 改语速。
- `profile=bright_young`：薄荷是明亮少女音，低落时不靠压低嗓子演，
  改成「收住亮度、停顿多一点」。

## 四、界面

「插件」页勾选 **声音** 之后，侧边栏才会出现 **声音** 板块（和表情包
同一个规矩：插件关着就不显示入口，避免点进去先提示“请先启用”）。

声音页里有：

| 分组 | 字段 |
|---|---|
| 模型接入 | 接口地址、API Key、模型、音色 ID、语言、音色基线 |
| 表达参数 | 语速（1.00）、Guidance、音量、最长一轮、缓存上限、超时 |
| 什么时候出声 | 策略、概率、冷却、每日/连续上限、最长字数、场景、内容过滤、范围 |
| 操作 | 测试连接（只查 `/v1/models`，**不合成、不花积分**）、清空缓存、保存 |

保存写 `config.json` 的 `voice` 段；开关写 `plugins.json`。
Key 输入框留空 = 不改，避免只调语速时把 Key 清掉。

### 一键安装 VB-CABLE

声音页顶部有「语音气泡准备」卡片：

- 内置官方 **VB-CABLE Driver Pack45**（31 个文件，SHA256 清单校验）；
- 点「一键安装 VB-CABLE」→ 弹 UAC → 安装程序用 `-i -h` 静默安装；
- 装完点「刷新声卡」，出现 `CABLE Input` / `CABLE Output` 即成功；
- 如果没出现，重启电脑/微信再刷新；
- VB-CABLE 是 VB-Audio Donationware，包内保留官方 `readme.txt`。

安装只负责驱动；微信麦克风仍要选 **CABLE Output**（声音页有「打开声音设置」按钮）。

## 五、什么时候出声

### 参考

| 项目 | 做法 | 可借鉴 / 不照搬 |
|---|---|---|
| [AstrBot TTS 情绪路由](https://github.com/muyouzhi6/astrbot_plugin_tts_emotion_router) | 四类独立策略：自动语音、文字+语音、分段、概率；按 UMO 黑白名单，长度/冷却/概率门控；手动 `tts_say`、LLM 工具 `tts_speak` | 借用「硬门槛 + 概率 + 冷却 + 会话级开关」；不照搬四种同时开，太复杂 |
| [AstrBot 自定义规则](https://docs.astrbot.app/use/custom-rules.html) | 每个会话单独开关 TTS，选语音模型 | 大肥鱼按会话开，不按全局一刀切 |
| [MaiBot MiMo 语音插件](https://github.com/Ling-LA/ling-tts-bot) | 默认 `llm_trigger` 语音优先；LLM 判断代码/网址/表格更适合文字；`random` 概率、`voice_only` 全语音；出站原位替换，避免文字+语音重复 | 借用「内容不适合就文字」「标记由模型判断」；**不照搬语音优先**，个人微信里每条都发音频太吵 |
| [AstrBot 讨论](https://github.com/AstrBotDevs/AstrBot/discussions/8608) | 提到个人微信不支持发送语音消息，是平台限制 | 所以当前先发音频文件；语音气泡另走虚拟声卡 |

### 大肥鱼的判定顺序

1. **硬门槛**：插件关 / 空文本 / 群聊（默认）/ 只对主人 / 超过最长字数 → 文字。
2. **内容门槛**：含链接、代码、表格、清单 → 文字。这些念出来没有意义。
3. **对方明确要**：「发条语音」「想听你说」「用声音」→ 出声；绕过冷却和场景，但每天上限仍算。
4. **模型标记**：`[[text]]` → 文字；`[[voice]]` → 出声（绕过概率/场景，仍受冷却）。
5. **冷却 / 每日上限 / 连续语音上限** → 文字。
6. **场景**：没勾的场景 → 文字。
7. **策略**：`request` 没要求不出；`always` 全出；`probability`/`auto` 掷骰；`preview` 只记日志。

### 推荐默认值

| 项 | 值 | 理由 |
|---|---|---|
| 策略 | 先 `request`，稳定后 `auto` | 头几天只在被要求时出声，确认音色/延迟/文件发送都正常 |
| 概率 | `0.2` | 五次里一次，像“偶尔想让你听见”，不是播报 |
| 冷却 | `600` 秒 | 同一会话十分钟内不连着发 |
| 每天上限 | `12` 条 | 积分闸门；也防止一天到晚都是音频 |
| 连续上限 | `2` 条 | 连着两条语音后强制回文字 |
| 最长字数 | `220` 字 | 约 45–50 秒；合成后超过 50 秒仍会改文字 |
| 群聊 | 关 | 群里的语音文件没有 @ 关系，别人不知道在念给谁 |
| 场景 | 亲密/低落/开心/日常/深夜开；拌嘴关 | 拌嘴时文字更稳，也不容易把气话念成撒娇 |
| 内容过滤 | 全开 | 链接/代码/表格/清单自动文字 |
| 发送方式 | **只发语音** | 命中语音后不再发同内容文字；语音失败才按 `fallback_text` 补文字 |

### 两种发送形式

- **音频文件（稳，推荐先跑）**：`send_media` 发 `.wav`，对方收到文件气泡，点开播放。
  个人微信协议不支持原生语音消息；这是目前最稳的链路。
- **语音气泡（实验性）**：参考 whale_girl 的 `VoiceSendEngine`，用 VB-CABLE
  把播放端 `CABLE Input` 接到微信麦克风 `CABLE Output`，同时 `SendInput`
  按住微信「发语音」快捷键，播完再松键。链路依赖微信版本、UIA 控件名、
  快捷键和虚拟声卡；失败分两级：
  - 还没按录音键：`started=false`，可以安全改发文字。
  - 已经按过录音键：`started=true`，**绝不补发文字**，因为对方可能已经
    收到半截语音；日志写「结果未确定」。
  气泡还限制 **1–55 秒**：太短微信可能不认，太长超过发送上限。

启动前必须：
1. 安装 VB-CABLE，Windows 声音里出现 CABLE Input / CABLE Output。
2. 微信「设置 → 快捷键 → 发语音」设成与声音页一致的组合（如 Ctrl+Alt）。
3. 微信麦克风选 CABLE Output；声音页播放端选 CABLE Input。
4. 以管理员身份运行（UIA 热激活需要）。

真实微信窗口的链路**已在本机实测过**（VB-CABLE 已装，微信麦克风接
CABLE Output、播放端接 CABLE Input）。实测中暴露并修掉三个只有真机才会
出现的问题：语音成功后 `hist` 未定义、气泡与文字的前台行为不一致
（`wake()` 只保证可见，气泡还要前台）、以及「按过录音键就绝不补发文字」
这条分级。代码按 whale_girl 的顺序实现，失败仍按上面的分级处理。

## 六、失败语义

| 情况 | 结果 |
|---|---|
| Key 不对 / 401 | 返回错误，不重试；日志写「Key 不对」 |
| 429 / 503 | 返回错误，按 `Retry-After` 让上层决定；**不自动连发** |
| 超时 | 返回错误；**不自动重试**（可能已经扣积分） |
| 200 但 body 为空 | 失败 |
| 返回的不是 WAV | 失败，打印前 300 字 |
| 时长 < 0.2s / 静音 / 削波 / 语速异常 | 体检失败，文件删除 |
| 缓存文件坏了 | 删掉重做，不把坏音频当答案 |

**缓存只存体检通过的。** 否则一次半截响应会被当成永久答案，之后
每次说到这句都是坏音频，而且不再重试。

## 七、和发送层的接缝

生成阶段（`handle` 里 `parts` 算完、挑表情之前）：

```python
_voice = self._plan_voice(msg, body, raw_reply, parts,
                          is_group=is_group, is_owner=bool(is_owner_chat))
entry["voice"] = _voice
```

`_plan_voice` 先过 `voice_policy.decide`，再合成；失败/预演返回 `{}`。
合成放在生成阶段，不堵投递线程。

投递阶段（`_deliver`）：

```python
# voice_only：先发音频；失败且 fallback_text 才发文字
if _voice:
    self._send_voice(msg, _voice["path"])
```

规则：

- 音频文件走 `send_media`（`.wav` 当普通文件，不是语音气泡）。
- 气泡走 `voice_bubble.send_bubble`：按住快捷键 → 播到 CABLE Input →
  松键；播完只报「已录完，未确认送达」。
- 气泡一旦按过录音键，失败就是不确定：**不补文字**，避免对方收到
  半截语音 + 完整文字两遍。
- 只发语音时**不** `remember_sent(reply)` —— 文字没到对方，不能记成发过。
- **命中语音后只发语音**：不再发同内容文字；只有语音在开始录音前失败、且 `fallback_text=true` 时才补文字。
- `voice_only` 且失败、`fallback_text=false`：这一轮只有日志，不补文字。
- 历史/记忆记的是正文，不是文件路径；她“说出口”的内容仍然是同一句。

## 八、成本控制

- **缓存**：同一句（同模型/音色/文本/指令/参数）不重复合成；默认上限 200MB。
- **只合成一轮一条**：3 条文字 + 3 条语音 = 6 条消息，太吵；
  整轮合成一条，条间用 `[停顿]`。
- **超长不出声**：`max_turn_chars=400`，超过就只发文字。
- **不做自动重试**：超时/5xx 可能已经扣费，重试会双花。
- **开发期用假服务**：`tools/selftest_voice.py` 不调用真实 API。

## 九、自检

```bash
python tools/selftest_voice.py
```

覆盖：标签保护、深夜/低落/拌嘴/群聊场景、speed 1.00、请求形状
（路径 voice、query output_format、xi-api-key、数字参数）、静音/截断拒绝、
缓存命中不重复请求、401 翻译；以及策略层：空文本/关闭/太长/冷却/
对方要/标记/链接/冲突场景/预演/request。

**不消耗积分**：假服务返回本地生成的 WAV。
