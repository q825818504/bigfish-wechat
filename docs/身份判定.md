# 她怎么判断"这句话是谁说的"

> 一句话：**拿不准的时候，私聊不回，群里只有叫了她才回。**

---

## 为什么需要单独说这件事

2026-11-04 那晚，她开始自问自答十几条停不下来。查下来第一个根因不是
"某个开关忘关了"，而是**程序没法可靠地判断一条消息是不是她自己发的**。

当时的写法：

```python
is_self = (sender == me) if sender else False
```

一个布尔值，两个输入，没有第三个值。它有三种"一声不响就判错"的情况，
而且**三种都倒向同一个方向：当成对方说的**：

| 情况 | 当时的结果 |
| --- | --- |
| 微信库里这条消息的发送者解析不出来 | 当成对方说的 → 回 |
| 读不到自己账号的 wxid | 每条都当成对方说的 → 回 |
| 群里解析发送者缺了分片 | 同上 |

"当成对方说的"意味着要回复，所以每错一次都是往自环里推一步。

---

## 现在的判断

改成三态：

| 结论 | 含义 |
| --- | --- |
| **自己** | 确定是角色自己发的 |
| **对方** | 确定是别人发的 |
| **拿不准** | 证据不足，不敢下结论 |

判断依据有两条，按顺序用：

1. **微信库里这条消息的发送者**（最可靠）
2. **群里正文开头的 `wxid_xxx: ` 前缀**（库里没有发送者时的兜底）

前缀**只认 wxid 形态**。`notes: 今天要……` 这种英文开头不会被当成人名。

---

## 拿不准的时候怎么办

这是刻意的取舍，两边不一样：

| 场景 | 行为 | 理由 |
| --- | --- | --- |
| **私聊** | **不回**，只在日志和判定记录里留一行 | 私聊里判错的代价是自问自答刷屏，比漏回严重得多 |
| **群聊** | **当对方处理，但必须这条真的叫了她**（`@` 或直接叫名字） | 群里漏回的代价只是"今天没接话"；而且有 @ 门槛兜着 |

**免检群不算"叫她"**。「这个群不用 @ 也回」是群级策略，不是"这一条冲着她说"。

### 你会看到什么

私聊里拿不准时，她**什么都不发**。不会提示"我没看清是谁发的"——
那种话术重复几次就穿帮了。

想知道当时发生了什么，看日志里的 `[跳过] … 拿不准是谁发的（sender_empty），不回`，
或者看证据记录（见下）。

---

## 拿不到自己账号时：不启动

如果读不到自己的 wxid，**所有判断都会失效**，所以程序会拒绝启动监听，
并说明原因：

> 读不到自己账号的 wxid。这种状态下没法判断哪条消息是自己发的，
> 所有自环防护都会失效，所以不启动监听。
> 请先确认微信已登录、并在「会话」页选定账号。

这不是保守，是唯一说得通的选择：不知道自己是谁的时候开口，
就是在赌"这条不是我自己发的"。那晚赌输了。

## 证据记录

只在**拿不准**的时候记一份，落在：

```
<数据根>/identity-trace/<时间>-<序号>-<会话>.json
```

确定是自己、确定是对方的，都不记——那是噪音，一天几千条会把真正要看的冲掉。

一条记录长这样：

```json
{
  "at": "2026-11-05T20:31:07.412",
  "rule_version": 1,
  "chat": "wxid_xxx",
  "is_group": false,
  "sender": "",
  "me": "wxid_me",
  "verdict": {
    "who": "unknown",
    "rule": "sender_empty",
    "evidence": [["sender", ""], ["me", "wxid_me"]]
  },
  "decision": { "proceed": false, "reason": "unknown_private" },
  "excerpt": "她那句话的前 80 个字"
}
```

保留最近 200 份，按文件名滚动删除。写失败**不影响聊天**。

关掉：

```json
{ "identity_trace": { "enabled": false } }
```
