# 部署与首次验证（v0.9）

> 这一份是给她"第一次真正活起来"用的。跑之前看完，跑完之后对照第 4 节。

---

## 一、部署

```bash
python tools/deploy.py
```

它会强杀进程 → 打包 → 覆盖 → 自检。如果你想手动分步：

```bash
python tools/build_portable.py
python tools/deploy.py
```

> ⚠ `deploy` 必须在 `build_portable` 之后（D-65）。反过来的话覆盖的是旧包。

部署完看一眼 `--selftest` 的版本号是不是 `0.9.0`：

```bash
dist\BigFish\BigFish.exe --selftest
```

## 二、第一晚：先开预演

### 为什么要预演

主动开口是**唯一一条没有你的消息作为起点的发送路径**。
它一旦跑飞，你只能杀进程 —— 而且记忆库会被污染。
所以第一晚不要真发。

### 怎么开

侧栏「插件」→ 点「主动」那张卡 → 打开 **预演模式（只记不发）**。

```
per_day            3
dry_run            ✓   ← 这一晚开这个
important_dates    （可以空着）
```

主动开口现在就是一张插件卡：开关在卡片右上角，参数在卡片里，改完点保存后
「预览」能看到她这一轮实际会收到什么。**没有单独的「主动」页面了。**

### 预演会发生什么

她照样判定、照样让模型复核，但**一条都不发**：

```
[主动] 想说：今天风挺大的｜life_share：她手头的事是「在收拾屋子」
[主动·预演] 老爸：今天风挺大的
```

这两行都进**日志**页。**而且预演仍然占当天额度** —— 不占的话你会看到
"她每分钟都想说话"，那看不出真实频次。

### 为什么不干脆关掉

关掉整张卡的话，闸门和判定都不跑，你什么都看不到。预演跑的是**完整链路**，
只是最后一步换成写记录。

## 三、第一晚还会发生什么（都是正常的）

### 她可能先开口

```
[主动] ✓ 老爸：今天那事儿还没说完吧
```

一天没看到也很正常：默认一天最多 1 条，而且要同时过四道闸
（9:00–22:30 / 两条之间至少 90 分钟 / 她醒着且精力够 / 你最近 30 分钟没在聊）。
这四道闸**不给开关**。

### 提炼关系卡

```
[关系] +1 条
[关系] 2 条没有原话依据，已丢弃（evidence not in transcript: 他以前说过…）
```

第二条是**好的**：说明证据校验在工作，编的那条被拦下来了。

只在距上次 6 小时以上才跑，跟着记忆反思一起。

### 情绪自己平复

每 10 分钟一次，不打日志。想确认的话看 `mood.json` 的 `lastDecayAt` 在动。

### 她到点睡、到点醒

```
[生活] 睡了（比计划晚 2 分钟，债 0）
[生活] 醒了（睡了 8.3 小时，精力 89）
```

睡着时你发消息：

```
[静默] 老爸：她睡了（23:41 入睡），大约 07:52 醒
[生活] 老爸 在她睡着时发了 2 条，记着，醒来补
```

第二天你说话时，prompt 里会多一段「## 刚看到」，她一句带过。

## 四、第二天早上怎么判断

去「日志」页搜 `[主动` —— 预演记录都在那里（`[主动·预演]` 是没发出去的那些）。

### 判断标准（按重要性）

| # | 看什么 | 好 | 不好 |
|---|---|---|---|
| 1 | **她说的话像人话吗** | 一句话，具体，有由头 | "想你了""在吗"这种空转 |
| 2 | **次数对不对** | 一天 0–2 条 | 一天五条以上 |
| 3 | **时间对不对** | 白天某处 | 半夜、你刚聊完 |
| 4 | **素材有没有编** | 每句都能对上 `life.json` 的 doing | 出现"我在开会"这种没写过的 |
| 5 | **有没有重复** | 同一件事只说一次 | 反复说"在收拾屋子" |

### 如果第 1 条不好

改 `bigfish/world.py` 里 `_maybe_proactive` 的复核提示词（`P.build_judge_request`），
或者改 `plugins/life.py` 注入的那段话。

### 如果第 2 条不好

`per_day` 调到 0（只停主动开口，追问还在）。

### 如果第 4 条不好

那是 `life.DOING_SLOTS` 里的事写得太宽（比如"在弄昨天没弄完的事"这种能被自由发挥的）。
收窄条目即可。

## 五、什么时候可以关掉预演

**第二天晚上**，如果你觉得预演记录里的话你愿意收到 —— 关掉预演。

关掉之后第一次真发，建议守着看：

```
[主动] ✓ 老爸：今天风挺大的
```

看到这行之后，**去微信看一眼那条消息真的到了**。

### 第一次真发之后要验的一件事

**她会不会把自己发的消息当成你说的。**

这是 0.4.1 那次事故的形态。验证方法：

1. 她主动发一条
2. 你**不回**
3. 看日志有没有 `[回环]` 或 `[静默]`
4. 看 `proactive.json` 的 `awaiting` 里那条还在不在

如果 `awaiting` 被清了但她没收到回复 —— 说明有东西把她自己发的当成"对方回了"。
立刻关掉主动，查 `identity` / `ledger`。

## 六、出问题先把这两件事做了

### 1. 关主动

「插件」→「主动」→ 右上角关掉那张卡（下一轮生效，不用重启）。

或者把参数「一天最多几条」设成 0 —— 那样只停主动开口，追问仍然生效。

### 2. 留现场

```bash
copy data\proactive.json  %TEMP%\proactive-bad.json
copy data\life.json       %TEMP%\life-bad.json
```

这两个文件加起来不到 4KB，但它们记录了"她当时以为自己是什么状态"。
没有这两个，事后只能靠日志猜。

## 七、这一晚需要盯的日志关键词

| 关键词 | 含义 | 正常吗 |
|---|---|---|
| `[生活]` | 她的状态推进 | 每天几十条 |
| `[静默] …她睡了` | 睡着没回 | 正常 |
| `[主动] 她自己否了` | 复核拦下来了 | **正常，而且越多越好** |
| `[主动·预演]` | 预演记录 | 预演模式才有 |
| `[主动] ✓` | 真发出去了 | 关掉预演之后 |
| `[主动] 她想了想，算了` | 追问掷骰没中 | 正常 |
| `[关系] +N 条` | 提炼到关系卡 | 一天几条 |
| `[关系] N 条没有原话依据` | 证据校验拦下了 | 正常 |
| `[回环]` | **自环防护触发** | 偶发正常，**连着出现要看** |
| `[熔断]` | 连发被拦 | **不正常，要查** |
