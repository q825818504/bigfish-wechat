# 主动开口与关系卡

> v0.9 起生效。这一层回答的是：**她会不会先开口，你们之间有没有历史。**

---

## 一、为什么这三块放在一起

它们共用一条链路：

```
本地闸门 → 掷骰 → 调一次模型复核 → 发送（三态记账）
```

任何一环松了，症状都一样：「她突然发了一条不该发的消息」。
分不清是判定太松、闸门漏了、还是复核没拦住 —— 所以文档也放一起。

---

## 二、主动开口：先掷骰子

这是整个项目**风险最高**的一块：它是唯一一条**没有对方消息作为起点**
的发送路径。一旦出问题，没有人能靠"不发消息"来止损。

所以第一原则没变：

> **宁可一整天不发，也不能发出一条不该发的。**

但 0.9.1 之前，"该不该发"是 `分数 >= 55 就发` —— 同一组条件永远同一个结果。
于是"她主动说话"变成一条规则，不是一个人的选择。真人同一天、同样的心情下，
可能想说、也可能不想说。

现在中间多了一步：**掷骰子**。

---

### 一条消息要走四步

```
① 闸门     条数 / 间隔 / 时段 / 她醒着 / 你不在聊     —— 不过就返回，一秒都不用
② 掷骰     40 分钟内掷过就跳过；掷了就记，中没中都算
③ 候选     七个来源各算一次分，取最高的那个；分数低于 40 不掷
④ 复核     一次模型调用，她自己判断"现在发合适吗"
```

只有第 ④ 步花模型。前三步全是本地计算。

---

### 五道硬闸门

| # | 条件 | 不过就 |
|---|---|---|
| 1 | 开关打开、今天条数没到上限 | 直接返回 |
| 2 | 距上一条 ≥ 45 分钟 | 直接返回 |
| 3 | 9:00–22:30 | 直接返回 |
| 4 | 她醒着、精力 ≥ 22 | 直接返回 |
| 5 | 你最近 30 分钟没在聊 | 直接返回 |

**第 3 和第 5 条不开放配置** —— 半夜发消息、在人家正聊的时候插话，
是灾难，不值得给一个开关。

⚠ 第 1、2 条只在上次**真的发出去**之后才生效。所以还需要第 ② 步的
"40 分钟内不重掷"，否则引擎每一分钟都会重掷，一天三条会在开机十分钟内发完。

---

### 八个来源，分两层

| 层 | 源 | 触发条件 | 分数 |
|---|---|---|---|
| **topic**<br>说什么 | `recall` 记忆里的待办 | 1.5–10 天前他说过「要去体检」这类有结果的事，之后没再提 | 84–91 |
| | `date` 重要日期 | 手填的日期，当天 + 提前一天 | 88 |
| | `open_loop` 未完话头 | 你最后一句有「等我/回头/明天」，之后 2–30 小时没再说话 | 66–81 |
| **tone**<br>为什么现在想说 | `mood` 心情 | 情绪变化 ≥8，且 18 小时没说过 | 60–70 |
| | `silence` 好久没聊 | 36 小时没对话 | 56–74 |
| | `whim` 没事也想说 | 醒着、精力 ≥45、20 小时没出现 | 60 |
| | `life_share` 手头的事 | 值得说 + 12 小时没分享过 | 58 |

**两层各取最高的一个，一起交给模型。**

这是 0.9.5 改的。原来是"八个来源抢一个"：排序取最高，其余全扔。
于是"我在收拾屋子"（58）和"我今天有点烦"（62）同时成立时，只会说出
前一件 —— 因为只能带一条理由进模型。

真人不是这样。真人会说"今天有点烦，在收拾屋子" —— 两件事叠在一起。

### 两层怎么合成一句话

```
有 topic + 有 tone
    他 3 天前说过「下周三要去体检」，之后一直没提结果。
    你心里有点事（工作压力），有点想跟他说说话。

只有 topic
    他 3 天前说过「下周三要去体检」，之后一直没提结果。

只有 tone
    已经 40 小时没怎么说话了，你有点想他
```

分数 = `max(topic, tone) + 8`（两层都有时），上限 95。
「有事可说」+「有话想说」本来就比单独一件更容易开口。

### recall 和 open_loop 的分工

| | 抓什么 | 例子 |
|---|---|---|
| `open_loop` | 你没接上的**话头** | 「等我忙完」→ 之后没再说话 |
| `recall` | 你说过、还没结果的**事** | 「下周三要去体检」→ 一直没提结果 |

后者才是真人主动开口最常有的由头。不是"你没回我"，是"我记得你有件事"。

它只在 `facts` 里找命中 `RECALL_KEYWORDS` 的（体检/面试/搬家/生日这类
"有结果"的事）。**刻意选得窄**：宁可漏掉，也不要拿"他喜欢吃辣"当由头去问
—— 那不是待办，那是画像，问出来像查户口。

问过一次就不再问（用 fact id 当 anchor）。

---

### 命中线怎么算

```
命中线 = 基础率(分数) × 时机因子 + 没中加成
```

**基础率**分两段 —— 日常想说话和"有话头没接"不是同一件事：

```
40–75 分    0 → 25%      日常（手头的事、心情、问候、没事想说）
75–92 分    25% → 70%    「有话头没接」「今天是他生日」
```

**时机因子**：

| 情况 | 因子 |
|---|---|
| 20 分钟内刚发过一条 | ×0.15 |
| 45 分钟内刚发过 | ×0.40 |
| 你 90 分钟内说过话 | ×0.50 |
| 6 小时以上没动静 | ×1.40 |

**没中加成**：连着没中一次 +8%，最多 +32%，掷中清零。

这一条存在的意义：沉默不该无限自我强化。没有它，条件最差的那几天会连着
不说话，而且第二天概率一模一样 —— 她越来越像一个坏掉的功能。

实际长这样（60 分、3 小时前说过话）：**14% → 22% → 30% → 38% → 46%**。

---

### 节奏长什么样

模拟 4000 天，每 120 分钟一次机会：

| 场景 | 平均 | 0 条 | 1 条 | 2 条 | 3 条 |
|---|---|---|---|---|---|
| 常聊（1 小时内聊过） | 1.35 | 9.4% | 52.4% | 31.9% | 6.2% |
| 正常（3 小时前说过） | 1.74 | 4.3% | 35.1% | 42.5% | 18.1% |
| 冷落（8 小时没说话） | 2.05 | 1.6% | 24.4% | 41.7% | 32.3% |

三件事在这个表里：

- **越不理她越主动**（1.35 → 2.05）。不是靠"补偿扔一条"，是靠时机因子 + 没中加成。
- **有"一句话都没有"的日子**。每天都说话，本身就不像人。
- **不会天天打满**。打满占 6%–32%，看你们这几天的状态。

这张表由 `tools/selftest_pace.py` 守着 —— 改任何参数，它会告诉你节奏变成什么样。

### 她怎么把这句话说出来

掷中之后**没有单独的"生成"和"复核"两步**，也没有 JSON 协议。
她走的是**和正常回复完全相同的拼装**（`EngineWorker._compose`）：

```
system   人格 860 / 心情 900 / 生活 870 / 说法 890 / 守卫 9990
user     你记得的事 + 这一轮 + 最近的对话
```

差别只在 user 段最后那条指令：

```diff
- 以她的身份回一条消息。
+ 没有人在跟你说话。是你自己想先开口。
+ 起因：她手头的事是「在收拾屋子」，这件事还没跟他说过
```

所以她说的话带着：她记得的事、此刻的心情、身体状态、对这个人的印象和
称呼、说话的习惯（分条、短句）。

⚠ 0.9.2 之前不是这样。那时主动消息用另一套 prompt：**人格 + 8 条历史**，
没有记忆、没有心情、没有生活。同一件事两种说法，人格密度完全不同 ——
用户能感觉到"她主动说的那句不像她"。这不是语气问题，是她开口时
手里根本没有自己的记忆。

**"算了"**：想说但觉得不合适时，输出一个 `-` 就不发（`clean_reply` 认这个
标记）。一次调用同时完成"想不想说"和"说什么"。

发出去也走 `_say_plan` 分条 —— 她主动说话是 1–3 条短句，不是一大坨。

这张契约由 `tools/selftest_compose.py` 守着：两种模式的 system 段必须
**逐段完全相同**，哪天有人只给正常回复加了一段，那一项就会红。

---

### 一天最多几条

「插件 → 主动」那张卡里的 `per_day`，默认 **3**。

这是**硬上限**，实际会比它少很多（上表：1.35–2.05）。
设成 0 = 不主动开口，但追问仍然生效。

重要日子在同一个卡片里填，一行一条：

```
12-25 她的生日
2027-03-08 搬家
```

每年重复只写月-日；只此一次的写完整日期。提前一天和当天各算一次。

## 三、发出去没人回：追问 or 忘记

真人有两种反应，而且两种都常见：

```
追问   隔几小时再问一句「在忙？」—— 只追一次，追完不追了
忘记   就这么过去了，下次说话时像没发生过
```

不是"必追"也不是"必不追"，是**掷一次骰子**：

```
基础概率        38%
有关系卡（称呼）  +14%
心情 ≥ 62        +6%
心情 ≤ 40        -10%
精力 ≤ 30        -8%
上限            62%
```

时间窗：发出 **6 小时后**才开始考虑，**30 小时后**放弃。

- 追了 → `followup_used = true`，不管有没有回都不再追
- 忘了 → 进 `dropped`，留着但**不主动提**

对方一说话，`note_peer()` 立刻清掉待追问 —— 不然她会在你回来之后又追一句"在忙？"。

## 四、关系：只有两条，但每条都要原话

### 两条

| kind | 是什么 | 例子 |
|---|---|---|
| `address` | 称呼是怎么变的 | 他从 10 月开始叫我「老头」，之前叫全名 |
| `unsaid` | 当时没说出口的话 | 他问我要不要一起回去，我没答，换了个话题 |

### 砍掉的三种（和理由）

| 砍掉的 | 为什么 |
|---|---|
| 我们之间的第一次 | 模型看到"第一次"就记一条，分不清"第一次听说"和"第一次做"。假阳性高到会污染整张卡 |
| 相处习惯 | `memory.habits` 已经在做。再开一层会两边各记一半、注入时互相矛盾 |
| 雷区 | 存"不要提什么"等于把内容再存一份，反而扩大泄露面。现在靠 visibility + topic 白名单在源头拦 |

### 铁律：evidence 必须能在原话里找到

`parse_bonds()` 做三道校验：

1. 结构对不对
2. `evidence` 是否 ≥ 4 个字
3. **`evidence` 是否真的出现在本轮素材里**（去空白后子串匹配）

第三条是关键 —— 它把"编一条关系"的成本拉高到"必须引用原话"。

为什么这么严：关系卡会进**每一轮**的 prompt。一条编造的
"他以前说过最怕被丢下"，会让她在之后几百轮里都按这个前提说话。

### 存哪

`memory.sqlite3` 的 `bonds` 表，和 facts 同一个库 —— 生命周期一样
（都会被纠正、被否决、被追溯来源），共用一套备份迁移。

去重靠 `UNIQUE(bank, owner, kind, text)`：同样内容再写是**更新**，不是插新行。

## 五、为什么没有「昨天」了

0.9.0 有过一个每日叙事：睡前让模型写三行"今天是什么样的一天"，存成
`<数据根>/journal/YYYY-MM-DD.md`，第二天作为「## 昨天」注入。

**0.9.1 撤掉了。** 那些内容 100% 来自当天的对话，而对话原文和提炼出的事实
都在记忆库里（`## 你记得的事` / `## 你认定的事`）—— 等于同一件事存了第三份。

真正想要的是「跨天连着」。那不是靠每天多写一个文件，是靠记忆检索能捞到昨天
的话；捞不到应该在检索里修，不该在旁边再养一个文件。

（顺带：这一版修掉了记忆检索的编码 bug —— 打包版里子进程输出按 GBK 写、
Node 按 UTF-8 读，汉字全变成 `�`。那才是"她记不住昨天"的根因。）

## 六、情绪会自己过去

`mood_judge.decay_only()` 每 10 分钟跑一次，挂在她生活的 tick 上。

以前衰减只写在 `judge_and_apply` 里 —— **只有聊天时才衰减**。
三天不说话，她的心情还停在上次那个点：不会从生气里缓过来，
也不会从高兴里平静下来。情绪没有"过去"这个动作，只有"被下一句话覆盖"。

现在：
- 总分按 `decayHalfHours`（默认 12 小时）半衰期往基线回
- 七根情绪按 90 分钟半衰期衰减

## 七、怎么验

### 真机跑一晚，盯这几行

```
[主动] 想说：今天风挺大的｜life_share：她手头的事是「在收拾屋子」…
[主动] 她自己否了（太晚了）              ← 复核拦下来的，正常
[主动] ✓ 老爸：今天风挺大的              ← 真发出去了
[主动] 她想了想，算了（没理由）          ← 忘了，不是 bug
[关系] +1 条                             ← 提炼到一条关系卡
[关系] 2 条没有原话依据，已丢弃（…）      ← 证据校验在工作
```

### 想确认闸门在工作

```
[主动] 被拦是常态，不刷日志
```

闸门拦截**故意不写日志**（一天几百次会刷屏）。想看的话把
`proactive.gate_block_reason` 的返回值临时打到 `self._log` 上。

### 关掉

主动开口现在是一个 **hook 类插件**（「插件 → 主动」那一张卡），
配置也只有这一个真源（`plugins.json` 的 `config.proactive`）。

| 关什么 | 效果 |
|---|---|
| 插件页关「主动」 | `World.tick_active` 整块不执行：不收集候选、不调模型、不发 |
| 参数「一天最多几条」= 0 | 不主动开口，但**追问仍然生效** |
| 参数「预演模式」打开 | 照常判断、照常自审，只把「本来会发什么」写进日志，不发出去 |

⚠ 时段窗口（9:00–22:30）、90 分钟间隔、她醒着且精力够、你最近 30 分钟
没在聊 —— 这四道闸**不给开关**。半夜发消息、在人家正聊的时候插话是灾难，
不值得配一个能关的开关。

关系卡没有独立开关：它并进了「印象」，跟着印象页走。

和画像一起放进 `## 你印象里的他`。

### 为什么 World 单独一层

`desktop.py` 的 `_run()` 已经是一个巨大的函数。0.4.1 那次自环事故的复盘写着：

> 防护全埋在 `_run()` 的闭包里，4500 行的函数，写不了测试 ——
> 所以这次事故没有任何用例能提前发现。

主动开口比回环防护更危险，所以这次不再往里塞：

```
引擎线程（5 秒）   本地判定，不调模型
后台线程           调模型，生成一句话，扔进 outbox
引擎线程（flush）  真正发送 —— UIA 是 COM/STA 的东西，跨线程会踩坑
```
