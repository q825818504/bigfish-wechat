# 生活状态：她会累、会睡、会手上有事

> v0.8 起生效。这一层解决的问题是：**她不再只存在于「你说话之后」。**

---

## 一句话

以前她的全部行为都发生在一个事件之后：收到消息 → 生成 → 发送。
没有消息的时候，程序里唯一的动作是 `while not self._stop: self.msleep(300)`。

现在多了一条自己的时间线：她会到点睡、睡够醒、精力随白天往下走、
手头在做一件具体的事、熬夜要还债。

---

## 三个变量

| 变量 | 含义 | 谁写 |
|---|---|---|
| `asleep` | 睡着 / 醒着 | 引擎每 5 秒 tick |
| `energy` | 0–100。醒着掉，睡着回，聊天也掉 | 引擎每 5 秒 tick |
| `doing` | 手头在做什么（**只有这里有的，她才可以说**） | 跨时段时换 |

状态文件：`<数据根>/life.json`，和 `mood.json` / `soul.json` 同级。

---

## 节律：她按自己的钟睡，不按你的最后一条消息

这一条是设计时被明确纠正的。

**错误的想法**：她最后一条消息之后 40 分钟也睡。

**为什么错**：你早上 9 点发一条，然后一整天没说话 —— 按那个算法她 9:40 就该睡了。
晚上 11 点你再发，她"刚醒"。这不是人，是回声。

**现在的模型**——两个时钟：

```
主时钟（她的）
    入睡 23:20 ± 42 分钟
    睡  8h20m ± 35 分钟
    每天不一样。你一整天不说话，她照样过完这一天。

扰动（你的）
    你深夜还在聊 → 她陪你多撑一会儿（每次 18~38 分钟，一晚最多 96 分钟）
    撑不住就睡，第二天才说"昨晚聊着聊着睡着了"
```

**睡眠债**：昨晚熬到 2 点 → 今天醒得晚（每欠 1 小时晚 30 分钟，上限 100 分钟）、
起床精力低、晚上更早犯困。债每天只还 45%，不会一次清零。

| 参数 | 值 | 在哪改 |
|---|---|---|
| 入睡基线 | 23:20 | `life.py: BEDTIME_BASE` |
| 入睡抖动 | ±42 分钟 | `BEDTIME_JITTER` |
| 基础睡眠时长 | 8h20m | `SLEEP_BASE_MINUTES` |
| 陪伴延长上限 | 96 分钟/晚 | `EXTEND_CAP_MINUTES` |
| 午睡概率 | 18%（13:00–16:00） | `NAP_PROBABILITY` |

## "一天"由醒来推动，不由时钟推

踩过的坑：最早想用「凌晨 4 点前算昨天」切天。但她的起床时刻是浮动的
（07:40 ± 35 + 晚醒最多 100 分钟 → 最晚 09:55）。任何固定分界线都会在
某个时间段和真实状态打架：

- 05:00 启动 → 按 4 点切，她算"今天"，被判成醒着，可她刚睡下两小时
- 07:00 启动 → 已经"新的一天"了，但 `wake_at` 是 08:10，还在睡

所以：**`day` 只在醒来那一刻推进**。冷启动（没有状态文件）才用
`asleep_window()` 按 epoch 猜一次，猜完立刻落盘，之后永远以状态为准。

> 这里有个必须记住的细节：入睡点会跨午夜（23:20 + 42 分钟抖动 = 次日 00:02）。
> 用"一天中的分钟数"比较时，次日的 00:02 会被折成 2，于是 23:50 被算成
> "早就过了入睡点"。**一切窗口判断都只能用 epoch。** 第一版就是这么错的。

## 睡着的时候收到消息

| 步骤 | 谁做 | 结果 |
|---|---|---|
| 1. 判定 | `plugins/life.py`（同一个插件的判定面） | 沉默，日志写「她睡了（23:41 入睡），大约 07:52 醒」 |
| 2. 记账 | 引擎（`life.note_pending`） | 记会话、条数、最后一条预览，**不叫醒她** |
| 3. 醒来 | 引擎 tick | `woke` 事件，日志写「睡着期间有 N 个会话找过她」 |
| 4. 带出来 | 下一轮 prompt | `## 刚看到` 段，一句带过，用掉即清 |

⚠ 默认**只对主人沉默**（可关）。睡着时被陌生人叫醒，比不理人更不像人。

⚠ 这一段**不是主动开口**：它只在对方已经发过消息、她又醒了的情况下生效，
走的完全是原来那条回复链（同一轮模型调用、同一套发送三态与账本）。
真正的主动消息（没人说话她也发）在 [`主动与关系.md`](主动与关系.md)，
那条单独走自环与账本。

## 为什么只占一个插件

「现在几点」「我醒着还是睡了」「睡着就不回」原本是三个插件
（`clock` / `life` / `sleep-gate`）。v0.9.1 合成了一个 —— 它们的数据源是同一份，
讲的是同一个事实：**她有自己的作息，现在是其中某一刻**。

拆开的代价很具体：要在插件页开三个开关才能让她"像个活人"；只开一个就会
说出半个真相（知道现在几点，但不知道自己已经睡了）；三个插件各自读盘、
各自判时间，同一轮里可能读到三个不同的"现在"。

所以插件系统现在支持 `scope="prompt+gate"` —— 一个插件既注入又判定，
两边共用一个开关。

## 手头的事：能不能说出口

`doing` 来自 `DOING_SLOTS` 的按时段取样，种子是 `day + 时段`：

- 同一天同一段，**永远同一个答案**。问三次「你在干嘛」，三次一样。
- 换时段才换事。
- **只有 `doing` 里写着的，她才可以说。** 没写就不许即兴编一件新事 ——
  编出来的事第二天对不上（D-36 事实必须有真来源）。

条目写的都是"不需要持续注意"的日常事（在看书、在收拾屋子、在等外卖），
不写"在开会""在医院"这类会让人问"那你怎么有空回我"的事。

## 出问题先看这三行日志

```
[生活] 醒着（精力 74）（手头：在看书）
[生活] 睡了（比计划晚 0 分钟，债 0）
[生活] 醒了（睡了 8.3 小时，精力 89），昨晚欠下 12 分钟，今天还了 5
```

- 「她怎么不理我」→ 看有没有 `[静默] ...：她睡了（23:41 入睡），大约 07:52 醒`
- 「她怎么突然说睡了」→ 看 `[生活]` 那几行的时间点
- 「她怎么一直没醒」→ 看 `life.json` 里的 `wake_at` 是不是被手改坏了
  （坏文件会退回一份全新的状态，日志里会出现 `[生活] 启动时她正在睡`）
