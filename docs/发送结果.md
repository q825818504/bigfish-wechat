# 她发没发出去

> 一句话：**"可能发出去了"和"没发出去"是两件事，程序以前把它们当成一件。**

---

## 为什么要分开

发一条微信要经过好几步：定位输入框 → 粘贴 → 检查内容落没落进去 → 按回车。
**任何一步都可能失败**，但失败的位置决定了消息到底发没发：

| 卡在哪 | 结果 |
| --- | --- |
| 桌面锁了、微信窗口不见了 | 一定没发 |
| 打不开会话、输入框归属不对 | 一定没发 |
| 内容没粘进去 | 一定没发 |
| **粘进去了，按回车时出错** | **不知道** |

最后一种最麻烦：回车可能已经投递了。如果程序当成"没发"处理，它会
再发一遍，对方就收到两条；更糟的是它会撤掉账本里这一笔，
于是这条消息读回来时没人认得 —— 自环就是从这儿开始的。

---

## 现在的三种结果

| 状态 | 意思 | 会怎么办 |
| --- | --- | --- |
| **已发出** | 确定发出去了 | 继续下一句 |
| **没发出去** | 确定没发 | 撤账、停下，不会自动重发 |
| **结果未知** | 可能已经发出去了 | 停下，**不重发**，**保留账本** |

### 你会看到什么

- 失败：`[发] ✗ …`
- 未知：`[发] ? …` 加一句  
  *「消息结果未知 —— 可能已经发出去了，所以不会重发。如果对方说没收到，是这一条。」*

这句话很重要：**未知不是失败**。如果对方说"你怎么没回我"，
先看看有没有这条日志，而不是让她再发一遍。

---

## 为什么未知时不重发

重发的代价是对方收到两遍；不发的代价是这一句没到。

两句重复的话，比一句没到更伤——尤其在她会自己接话的场景下，
重复的那条会以"收 老爸：…"的形式读回来，又变成新一轮的输入。

---

## 怎么判断"回车按过没有"

底层库自己做了一个标记：

```python
# 按回车之前
self._send_attempted = True
e.SendKeys("{Enter}")
```

它保留了"有没有走到这一步"，所以程序能分清"卡在回车前"和"按了回车之后才炸"。
这个标记一直存在，只是之前没人读。

---

## 已知的边界

- **"粘贴有没有落进去"这一层不归程序管**：底层有自己的相似度检查，
  不达标就不按回车。
- **不做"事后去库里查一眼"**：微信写库有延迟，查不到不等于没发，
  查到的也可能不是这一条。结论不可靠，不如老实说"不知道"。
- **未知之后这一轮就断了**：后面还没发的分条不会补上。
  宁可只说半句，也不要补上一串可能重复的话。
