# 作用域配置（C-1）

> 一句话：**有些开关只该对某个会话生效，而以前的配置表达不了这件事。**

---

## 为什么要有它

2026-11-04 自环事故的第一个根因不是"读错了路径"，是配置层**没有"会话级"这个概念**：

```python
# 事故时的写法（app.py）
if msg.is_self and not (cfg.allow_self and msg.chat_id == "filehelper"):
```

一个全局布尔 + 一个写死在代码里的白名单。后果是：

- 任何一个人需要"回应自己发的消息"（自测通道），等于所有人的私聊都开着它；
- 想改白名单只能改代码。

现在白名单由配置表达，代码里不再有那个常量。

---

## 三层

```text
scopes.chat[<会话 id>]        ← 最优先
scopes.account[<Bot wxid>]    ← 其次
scopes.global                 ← 再次
代码默认值                     ← 兜底
```

配置文件长这样：

```json
{
  "scopes": {
    "global":  { "group_reply": true, "max_reply_chars": 300, "quiet_hours": [] },
    "account": { "wxid_bot_xxx": { "max_reply_chars": 200 } },
    "chat":    { "wxid_dad": { "allow_self": false },
                 "filehelper": { "allow_self": true } }
  }
}
```

---

## 三态：`false` 和"没写"不是一回事

布尔字段有三种状态：

| 写法 | 含义 |
| --- | --- |
| 不写，或写 `null` | 继承上一层 |
| `true` | 显式开启 |
| `false` | 显式关闭 |

**为什么非要分开**：如果 `false` 和"没写"都表示同一个东西，
那"我在这个会话里把它关了"和"我从来没配过它"在数据上无法区分——
用户改了配置、看文件也改了、行为就是不变。这正是 D-61 那个形状。

数字和列表没有 `false`，但仍然要区分"没写"和"显式清空"：

| 字段 | 没写 | 给了值 |
| --- | --- | --- |
| `max_reply_chars` | 继承 | 正整数覆盖；`0` = 不截断 |
| `quiet_hours` | 继承 | `[]` = 这个会话没有免打扰 |
| `group_allow_all` | 继承 | `[]` = 显式清空 |

> ⚠ 所以代码里**不能用 `d.get(k) or fallback`**。它会把 `[]`、`0`、`False`
> 一起吞掉，正好把"显式清空"变回"继承"。`scopes` 内部一律用 `k in d` 判断。

## 键：只用 id，昵称是只读别名

会话层的键必须是平台 id：

| 类型 | 写法 |
| --- | --- |
| 私聊 | 对方的 `wxid_xxx` |
| 群聊 | `123456789@chatroom` |
| 自测通道 | `filehelper` |

历史配置里有昵称键（`"老爸"`）也能读，但只做**别名**：
读取时通过微信数据库解析成 id 再比对；解析不到就是"未命中"（不报错、不误命中）。

**写入永远写 id。** 用昵称当键会被拒绝——微信改名之后那条配置就静默失效了。

---

## 允许按会话配的字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `allow_self` | bool | 允许回应自己发的消息（自测通道） |
| `group_reply` | bool | 这个群要不要参与 |
| `group_allow_all` | list | 无条件回复的群（不需要 @） |
| `max_reply_chars` | int | 单轮回复字数上限 |
| `quiet_hours` | list | 免打扰时段 |

`quiet_hours` 两种写法都认：

```json
"quiet_hours": ["23", "0", "1"]          // 整点
"quiet_hours": ["23:00-07:00"]           // 区间，两端都含，跨夜可选
```

## 旧的 `auto_reply.*` 怎么办

**读得到，不会自动改文件。**

| 旧位置 | 新位置 |
| --- | --- |
| `auto_reply.group_reply` | `scopes.global.group_reply` |
| `auto_reply.group_allow_all` | `scopes.global.group_allow_all` |
| `auto_reply.max_reply_chars` | `scopes.global.max_reply_chars` |
| `auto_reply.quiet_hours` | `scopes.global.quiet_hours` |
| `auto_reply.allow_self` | ⚠ **不是** global，见下 |

新路径优先。旧字段永远不删，方便回滚。

### `allow_self` 是例外

旧的 `auto_reply.allow_self: true` **不会**被当成全局值读——
那会让每个会话都拿到 true，等于把事故开关重新打开。

它按"本来的意图"处理：**只对 `filehelper` 一个会话生效**。
所以线上那份老配置可以原封不动继续跑，而私聊已经安全了。

想给别的会话开自测，必须显式写：

```json
"scopes": { "chat": { "wxid_xxx": { "allow_self": true } } }
```

---

## 生效时机

**每轮重读**。改完配置，下一条消息就按新值判断，不用重启程序。

代价是一次 JSON 解析（< 1ms），换来的是永远不会出现"改了不生效"。

## 排障

```python
from bigfish import scopes
print(scopes.explain(cfg, chat_id="wxid_xxx"))
```

会逐字段打印"最终值 ← 来源层"，并列出：

- `scope_chat_key_unresolved`：某个会话键既不是 id 也解析不出 id（微信没开时常见）
- `scope_value_type` / `scope_value_range`：值类型不对，已被忽略
- `scope_legacy_path`：还在用旧路径
- `scope_account_not_found`：`scopes.account` 里没有当前账号

---

## 已知边界

- 昵称解析依赖微信数据库。微信没开时打开设置页，某些键会标"未解析"，这是正常的。
- `group_allow_all` 按会话解析时，语义是"**这个群看到的那份名单**里有没有它自己"。
  所以 `scopes.chat[G].group_allow_all = [G]` 才等于给 G 开了 allow_all。
- 本次只下沉了五个"行为开关"。`say.*` / `listen.*` / `llm.*` 仍是全局，后续再扩。

## 界面上怎么改

「会话」页每一行右侧有一个 ⚙（鼠标移到行上才显出来）。点它打开这个会话的配置。

每一项下面都有一行小字，说明**这个值现在从哪来**：

| 小字 | 意思 |
| --- | --- |
| 本会话 | 你在这一项上覆盖过 |
| 继承自全局 | 没设过，跟着 `scopes.global` |
| 继承自账号 | 跟着 `scopes.account[账号]` |
| 代码默认值 | 谁都没设，用程序里的默认 |
| 旧配置的全局开关（仅自测会话） | 旧的 `auto_reply.allow_self` 还在生效，只对 filehelper |

**布尔字段**是三段：`继承 / 开 / 关`。选「继承」就是把覆盖删掉。

**数字和列表**直接改输入框就行——一改就是覆盖，不用先点按钮。
右边的「继承」按钮用来**撤销覆盖**（当前就在跟随时它是灰的，因为没什么可撤销的）。

改完点「保存」才落盘；有未保存的修改时底部会写出来。保存后**下一条消息就生效**，
不用重启。

### 改不动的两种情况

- **键必须是 id**。弹层的键来自会话列表（本来就是 wxid / 群 id），
  所以正常操作碰不到这个限制；手改 JSON 时用昵称会被拒绝。
- **昵称键解析不出来**。老配置里可能残留昵称键，微信没开时解析不了，
  弹层底部会明说「某个键既不是 id 也没解析出 id」。
