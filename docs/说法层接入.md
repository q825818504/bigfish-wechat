## 三、已接入的位置（供 review）

### 1. `AppConfig`（`app.py`）

新增 7 个字段，从 `config.json` 顶层 `say` / `listen` 段读取：

```python
say_enabled / say_max_parts / say_part_chars
listen_enabled / listen_quiet / listen_max_wait / listen_max_batch
```

### 2. `BigFishApp`：`handle()` 拆成四个方法

| 方法 | 职责 |
|---|---|
| `_accept(msg)` | 过滤（空/自己/安静时段）+ 群聊判定，返回 `BatchMessage` 或 `None` |
| `enqueue(msg)` | watcher 回调：只 `batcher.feed`，不调模型 |
| `handle_batch(batch)` | 一批 → 一次模型 → 分条 → 逐条确认发送 |
| `handle(msg)` | 兼容旧调用：单条立即处理，不攒批 |

`main()` 里 `watcher.on_message = app.enqueue`，并在 `watcher.start()` 前 `app.start()`、退出时 `app.stop()`。

### 3. `build_prompt`：加了分条协议

「这一轮」的要求里多了两行：

```
- 一次只说一件事。想说的多就分几条发，每条之间用单独一行 {{split}} 隔开
- 一般 1~3 条就够；不要为了凑条数把一句话拆碎，也不要把标记写进正文
```

`{{split}}` 常量是 `app.SPLIT_MARK`，必须与 `say.SplitPolicy.marker` 一致。

### 4. `handle_batch` 的发送段

```python
parts = split_reply(reply, SplitPolicy(max_parts=..., part_max_chars=...))
if is_group and last.author:
    parts[0] = f"@{last.author} {parts[0]}"      # @ 只加第一条
gaps = plan_pacing(parts, PacePolicy(seed=batch.chat_id))
outcome = send_parts(self.sender.send, self.reader.messages,
                     last.chat_name, parts, gaps, log=self.log,
                     on_confirmed=lambda _i, m: conv.add(self.soul.address or "我", m.content))
```

`on_confirmed` 是关键：**只有库里确认了才写进历史**，发失败不会记成"我说过"。

## 四、配置（`config.json`）

```json
"say": {
  "max_parts": 4,
  "part_max_chars": 50,
  "min_chars": 3,
  "llm_split": false,
  "workers": 2,
  "strict_confirm": false
},
"listen": {
  "quiet_same_author": 2.0,
  "quiet_different_author": 0.8,
  "quiet_mention": 1.0,
  "quiet_media": 4.0,
  "max_wait": 8.0,
  "max_batch": 8
}
```

| 键 | 默认 | 说明 |
|---|---|---|
| `llm_split` | `false` | 长回复且模型没给 `{{split}}` 时，**多调一次模型断句**（慢一倍，换更像人的断法） |
| `workers` | `2` | 不同会话的并发批次数；同一会话始终串行 |
| `strict_confirm` | `false` | `true` = 库里没确认就停；`false` = L1 成功就继续（默认，避免话说一半） |

两个开关独立：
- 只要分条、不要攒批 → 不接第 3 步的 flush 线程，`enqueue` 里直接 `handle_batch(单条批)`
- 只要攒批、不要分条 → `handle_batch` 里用 `sender.send` 一次发完

## 八、已知限制

| 限制 | 说明 |
|---|---|
| 分条器不改写文本 | 「明天去长坂坡游玩」不会变成「那明天去长坂坡玩吧」；改写靠 prompt 里的分条协议，模型给了 `{{split}}` 才按 3 条走 |
| 确认默认不阻断 | 落库慢时日志会出现 `unconfirmed`，但**继续发**（L1 已证明回车按下了）。要严格就开 `strict_confirm` |
| 最后一条异步确认 | 发完立刻返回，后台 3 秒内查库；确认到才写历史，确认不到就只在日志留痕 |
| 群聊 @ 只加第一条 | 后续条不带 @，这是刻意的（每条都 @ 很吵） |
| 同会话串行、跨会话并发 | `workers=2` 时两个群可以同时回；第三个群排队 |
| LLM 断句默认关 | 开了会多一次模型调用，延迟约翻倍；只在「回复长且模型没给标记」时触发 |

### 面板里能调什么

| 参数 | 默认 | 作用 |
|---|---|---|
| 最多几条 | 4 | 分条上限，超过合并（不截断） |
| 单条上限（字） | 50 | 超过在逗号/空格处再切 |
| 每字等待（秒） | 0.09 | 节奏斜率：`0.8 + 0.09 × 字数^0.8` |
| 单次停顿上限（秒） | 3.5 | 再长也不会超，免得像卡住 |
| 整轮总时长上限（秒） | 12 | 超过等比压缩 |
| 引号内不切 | 开 | 引用的原话不截断 |
| 最后一条异步确认 | 开 | 最后一条不陪等落库 |
| 严格确认 | 关 | 库里没确认时是否停 |

### 两个入口都生效

- **命令行**（`bigfish/app.py`）：`_refresh_say_config()` 每批从插件读一次
- **桌面端**（`bigfish/desktop.py`）：`_say_plan()` 每轮从插件读一次

两处读同一份 `<数据根>/plugins.json`，所以面板改一次，两边一起变。

> 桌面端原来是自己一次性 `sender.send()`；这次改成逐条发送 + 条间 `sleep`，
> 表情包、记忆写回、心情判断都还在最后一条之后照常执行。

## 十一、表情位置（不固定放最后）

### 两边的判据

| 项目 | 做法 |
|---|---|
| **MaiBot** | 表情是一个独立工具 `send_emoji`，模型自己决定何时调：可以先发图再 `reply`，也可以 `reply` 时用 `attach_emoji` 跟在文字后 |
| **AstrBot** | 提示词里写死判据：**「轻松、即时且图片足够表达时，可以只发一张原图；需要回答问题、解释或表达重要细节时先说清文字。严肃、敏感、冲突或容易显得嘲讽的场景谨慎选，不为丰富形式硬加图」** |

### 我们的实现（auto）

位置不再固定「跟在文字后」，改成可配置 + 一条自动规则：

| 条件 | 位置 | 例子 |
|---|---|---|
| 回应 ≤12 字 **且** 情绪强度 ≥60 | **先发表情** | 骄傲/得意/惊讶/无语 —— 先给反应，再补一句 |
| 其它（长回复、解释、安慰） | **跟在文字后** | 「今天去了长坂坡，路上…」 |
| 插件里选「总是先发」 | 固定 before | 用户自己定 |
| 插件里选「总是后发」 | 固定 after | 回到旧行为 |

代码在 `bigfish/plugins/__init__.py:_sticker_position()`，参数在 `sticker` 插件的「表情位置」。

### 顺序

```
前置：  表情 → 文字条1 → 文字条2 …
后置：  文字条1 → 文字条2 → 表情
```

前置时表情只发一次，不会每条都跟。

## 十三、打包进 exe

### 打之前必须补 spec

`packaging/bigfish.spec` 的 `hiddenimports` 里要显式列三个模块，否则打包版会在**真聊天时**才 ImportError：

```python
"bigfish.say",
"bigfish.listen",
"bigfish.plugins.say",
```

原因和文件里 memory/plugins 的注释一样：这些 import 都在函数体内
（`handle_batch` / `_say_plan` / `_load_builtins`），启动时走不到。

### 打包命令

```cmd
cd /d D:\大脑\bigfish_repo\bigfish-wechat
rmdir /s /q dist
python -m PyInstaller --noconfirm --clean --distpath dist --workpath build packaging/bigfish.spec
```

打完把外部资源补到 `dist\BigFish\`：`ui\`、`bridge\`、`config.example.json`、`README.md`
（`packaging\build.bat` 的第 3 步做的就是这个）。
